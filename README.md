# LOONG JUMP 品牌出海供应链控制塔

这是从原内部备货原型升级而来的正式上线版本，覆盖五个国家站点的 TikTok、Shopee 及线下渠道。

## 新增用户

自有服务器的公司账号版本支持管理员在网页直接开通员工账号：侧栏“用户管理” → “＋ 新增用户” → 填写姓名、邮箱、岗位、初始密码及权限范围 → “创建用户”。初始密码至少12个字符，启用后即可使用邮箱和密码登录。重复邮箱不会覆盖原账号，新增操作会进入审计日志。

运营必须选择站点及 TikTok／Shopee 渠道；销售自动绑定印尼线下分销。Sites／ChatGPT 登录版本仍需员工先登录，再由管理员分配岗位。详细步骤见 [服务器部署与恢复](docs/服务器部署与恢复.md)。

## 库存与销售表格导入

需要录入库存或销售明细的页面提供“下载导入模板 → 选择 Excel / CSV → 预览并校验 → 确认导入”。包括库存盘点／期初库存、历史到仓、平台销售、目的地与历史海运批次到仓、批发订单明细、批发实际发货和单条退货验收。详见 [库存与销售导入操作说明](docs/库存与销售导入.md)。

库存和历史到仓每次最多200行，整批事务写入，错误或并发冲突时整批回滚；重复文件内容及到仓单号受保护。平台销售最多5000行，保持运营账号本站渠道权限。批发订单最多20个SKU，导入后仍按原审批和实际交付流程处理。

## 运营月度备货导入与删除

运营账号在“补货驾驶舱 → 提交本月备货需求”下载模板，填写 SKU、备货数量，商品名称和调整原因可选。支持 Excel（`.xlsx` / `.xls`）和 CSV，每次最多1000行、10MB；SKU须已在系统维护，数量须为正整数。重复SKU、未知SKU或格式错误会阻止整批导入。

- “替换当前清单”只保留文件中的SKU；“合并到当前清单”保留其他SKU，同SKU覆盖数量，不累加。
- 预览并确认导入后，可修改数量、原因，也可逐行“删除”；“撤销上一步”可撤销最近一次删除或导入，继续编辑后该撤销入口会清除。
- 导入和删除先修改页面清单，点击“提交 YYYY-MM 需求”后保存。重新打开会载入已提交清单，已删除SKU不会被系统建议自动加回。离开页面前请先提交，否则未保存修改会丢失。
- 删除只移除本月备货明细，不删除商品主数据或库存。若删除全部明细，须勾选“确认本月无需备货”并填写说明后提交。
- 账号只能提交自己绑定的站点和渠道；已进入审批或已批准的计划继续按原流程走变更审批。

## 已落地的关键优化

- ChatGPT 身份登录，不再使用前端明文密码。
- 保留官方私有安全验证，验证后展示 LOONG JUMP 品牌欢迎页与“致敬每一位奋斗者！”主题。
- 欢迎页、系统侧栏、浏览器图标与分享图统一使用品牌战略手册中的新版飞鸟双翼 Logo。
- 角色与站点权限全部由服务端校验。
- 使用 D1 数据库持久化，写入失败会明确提示。
- 库存采用“余额＋不可直接修改的流水”双记录。
- 手工销售和 Excel/CSV 导入统一扣库。
- 文件指纹、到仓单号唯一约束，防止重复扣库和重复入库。
- 库存不足时保留负库存并进入异常中心，不再静默归零。
- 到仓必须按“站点＋渠道”分配，不再 TikTok/Shopee 各半估算。
- 五站双渠道共 10 项全部提交后，月度计划才能进入审批。
- 供应链发起、管理员审批；申请人不能审批自己提交的计划。
- 生产和运输节点按当前负责人校验，推进时必须填写凭证。
- 补货驾驶舱按“站点＋渠道＋SKU”读取连续 28 个自然日数据，以近 7 天日均作为主要需求速度，并用 28 天均值校准。
- 库存、海运在途和生产中批次分层核算；转入海运时必须填写预计到仓日期。
- 安全库存根据销量波动、生产＋海运交期和目标服务水平自动计算，不再使用统一百分比。
- 同时给出“建议海运补货”和“建议启动生产”两类决策，并显示可售天数、断货风险、销量趋势和数据可信度。
- 供应覆盖图与 28 天趋势图支持会议现场横向比较。
- 新增新品孵化与首批备货流程：管理员每月7号发起，选款、五站双渠道调研与种草、财务测算、打板确认和首批生产全部在线留痕。
- 新品调研与种草要求五站 TikTok、Shopee 共10个站点渠道分别提交；毛利和打板均设继续或止损门槛。
- 打板通过且首批站点渠道分配合计正确后，自动生成默认3000件的正式生产批次并接入原生产运输流程。
- 销售数据中心展示五站双渠道每日更新情况和近7天热销SKU，管理员、供应链与工厂共享同一销售口径。
- 全链路批次补齐备货确认、工厂生产、渠道分配、海运、到港、派送、到仓与上架确认；运营可查看本人站点渠道进度。
- 到仓后不直接结束，必须由各站点渠道运营分别提交上架凭证，全部确认后批次才闭环。
- 节点超过建议跟进时限未更新时自动进入停滞预警，页面显示当前责任岗位、最近更新时间、ETA与业务凭证。
- 管理员可导出不含密码的全量 JSON 备份。
- 销售导入增加平台来源编号、90天日期边界和可审计冲销；冲销会恢复库存，但原记录不会删除。
- 销量均值只使用实际完成导入的日期，缺失日期不再错误地按零销量计算。
- 库存拆分为“可售、待上架、预留、隔离”四个口径；到仓不再直接增加可售库存，质检隔离放行后仍须运营确认上架。
- 运营盘点只提交差异单，由供应链或管理员复核；复核时会校验库存是否已发生后续变化。
- 补货量支持 MOQ、下单倍数、装箱数、体积与仓库容量约束。
- 新增供应商、工厂、承运商和目的仓主数据；工厂与承运商必须绑定具体责任账号。
- 采购生产链调整为“管理员批准 → 供应链确认供应商接单 → 工厂接单并承诺交期 → 更新进度 → 完工 → 供应链质检”。
- 发运采用“跨系列运输主批次 → 目的地分腿 → SKU明细”：同柜可装多个系列，每个目的仓独立维护 ETD、ETA、到港、清关、派送、到仓和上架状态。
- 数据库在并发层阻止超完工量发货、超发货量分配、超分配量收货、重复上架和库存分桶负数。
- 总览新增按账号责任生成的“我的待办”，管理员权限测试同时显示菜单、写入动作和可读取数据域。

## 权限

- 管理员：全局数据、审批、账号授权、备份。
- 运营：只能查看和操作本人绑定的站点＋渠道。
- 供应链：汇总月度计划、维护备货参数、推进供应链节点、到仓入库。
- 工厂：只处理分配给本账号的生产单，包括接单、进度和完工。
- 海运：只处理分配给本账号的目的地运输分腿，包括海运、到港、清关、派送和 ETA；不能到仓入库。
- 运营主管：统筹新品种草测试、阶段止损决策和打板确认。
- 新品开发：提交候选款开发理由并确认实物样品。
- 财务：提交新品成本、毛利率和盈亏平衡测算。

首位访问正式站点并完成 ChatGPT 登录的成员会成为管理员。上线前必须先把站点访问范围设为公司成员，再由管理员安排其他成员登录并分配角色。

## 本地检查

需要 Node.js 22.13+ 和 pnpm 11。

1. 安装依赖：`pnpm install`
2. 类型检查：`pnpm check`
3. 业务规则测试：`node --test tests/business-rules.test.mjs`
4. 本地运行：`pnpm dev`
5. 生产构建：`pnpm build`

本地运行时系统使用一个仅限 localhost 的“本地管理员”身份；部署后该身份不可用，必须通过 ChatGPT 登录。

## 数据迁移

数据库结构位于 `drizzle/`，其中 `0001_redundant_master_chief.sql` 增加动态供应参数，`0002_first_puck.sql` 增加新品项目与阶段记录。正式导入旧系统数据前，应先整理 SKU 编码、站点、渠道和期初库存，再通过库存盘点或专门迁移脚本写入，避免把旧原型的示例数据当作真实库存。
