# 网站询盘接入与客户转化

本功能把网站询盘接入「印尼线下批发 → 网站询盘」，不直接创建客户、订单或资金流水。现有财务审批、库存预留、实际出库、回款、开票和客户收货流程继续使用原规则。

## 操作流程

1. 网站保存询盘时，同一事务写入投递队列。网站原询盘编号是业务唯一键，不依靠文件名、客户姓名或推送次数去重。
2. Admin 收到签名有效的推送后保留原始需求及来源版本。没有销售账号对应关系的询盘进入待分配池。
3. 管理员选择 Admin 负责人，填写依据。勾选「保存这两个销售账号的对应关系」后，这位网站销售后续的新询盘自动分配给该负责人。既有待分配记录仍由管理员核对后分配。
4. 销售在自己的询盘内记录沟通、下次跟进日期及客户资料。资料不齐可以保存跟进，不能创建客户。未分配的线索只有管理员可见。
5. 核实客户身份后，新建客户或关联同一负责人名下的已有客户。一个客户可以关联多条询盘；相同联系方式只提示人工核对，不自动合并。姓名和电话匹配已有客户时阻止重复建档。
6. 仅国家已确认是印尼且业务类型为批发的线索可转入客户。OEM、其他国家、国家未填的记录保留原分类；管理员核实实际目的国及业务类型并填写依据后，才可转业务，原始需求保留。
7. 「创建线下出库申请」打开原订单表单。点击「带入询盘客户」后手动选系统 SKU、数量和 IDR 报价。网站产品编号不冒充系统 SKU，网站询价不作为已批准售价。
8. 订单保存询盘来源，询盘页可打开关联订单查看发货与回款。现金类仍先确认到账再发货；寄售继续按客户实际售出结算。重复投递询盘不会创建订单或扣库存。

客户必须填写：客户名称、联系人、真实有效电话、城市、收货地址。仅邮箱的询盘仍需补电话。禁止使用默认地址、虚构电话或姓名相似自动合并。

## 同步协议与权限

- 专用入口：`POST /api/integrations/website-inquiries`，仅接受服务端 HMAC-SHA256 签名，不使用浏览器登录身份作为集成凭据。
- 两端环境变量：`LOONGJUMP_INQUIRY_SYNC_SECRET`，至少 32 个字符；正式环境应使用安全随机生成的共享密钥。不要使用示例值，不写入仓库、网页或 URL。
- 来源默认 `loongjump-website`，可用 `LOONGJUMP_INQUIRY_SOURCE` 在两端设置相同值。
- 网站额外配置 `LOONGJUMP_ADMIN_SYNC_URL=https://admin.loongjump.com/api/integrations/website-inquiries`。生产仅接受 HTTPS、固定路径，无 URL 用户名、密码、查询参数或重定向。
- `x-loongjump-timestamp` 为毫秒时间戳，允许偏差 5 分钟；`x-loongjump-signature` 为 `HMAC(secret, timestamp + '.' + rawBody)` 的十六进制值。原始请求最大 64KB。
- 报文含 `schemaVersion=1`、`source`、`externalId`、递增 `revision`、来源时间、原销售身份、询盘资料。
- Admin 唯一约束 `(source, external_id)`；相同版本相同内容重试返回原 lead ID；同版本不同内容返回 409；旧版本不覆盖新版本。
- 网站以独立 outbox generation 追踪自动分配及人工更新。每个待投递版本保存固定报文，断网或回执丢失后重试报文不变。
- Admin 已核实资料、人工归属、客户关联不被网站更新覆盖。网站负责人改变时，非人工分配记录标记待复核。
- 网站国家来自客户填写的字段，不能用访客 IP 推断收货国家。
- Admin 管理员可以分配和确认范围；印尼销售及印尼运营仅处理自己负责的线索。财务、供应链仍按现有权限处理已生成的订单。接口和界面同时限制访问。
- 线索跟进、分配、范围确认、客户转换写入不可覆盖的事件记录。修改使用版本校验，重复提交使用 operation ID。

## 运行与发布

网站 Node 服务每 15 秒扫描队列，每轮最多 20 条；失败按指数退避重试，最长间隔 1 小时。处理中使用 60 秒租约，进程重启后恢复。只有匹配原询盘编号、来源和版本的有效回执才视为成功，HTTP 200 的登录页不算成功。

网站管理页「询盘与客户」显示投递状态；管理员可查看配置状态、已送达、待同步及重试数。`/api/ops/admin-sync` 仅网站 owner/manager 可读。后台不会记录远端响应正文或密钥。重试不自动删除失败记录。

上线步骤：

1. 备份两端数据库，按现有发布流程验证恢复包；本次 Admin 新迁移为 `0036_website_inquiries.sql`，网站为 `0004_admin_inquiry_sync.sql`。
2. 先发布 Admin 接收端，并通过服务器安全环境文件配置共享密钥和来源。未配置时专用入口返回 503，不降低普通业务接口的登录要求。
3. 发布网站 Node 服务并配置接收地址、相同密钥和来源。网站迁移会把已有询盘加入队列；无配置时仅积存，不向任何外部地址发送。
4. 观察投递状态，在 Admin 建立销售对应关系；核对未分配记录、业务范围及真实客户资料。
5. 用明确标识的测试询盘核验原编号、销售归属和重复投递。正式订单及资金记录由业务人员确认后操作。

当前自动投递调度器由网站 **Node 服务**运行。Cloudflare 构建保持兼容，但本次没有为网站部署 Cloudflare 定时消费者；若未来切换网站托管方式，需要同时接入队列消费者，不能只发布静态前端。

停止同步可移除网站的同步配置并重启服务；队列保留。业务表新增后不可直接回退旧数据库结构。Admin 不回写网站销售状态，以免两边互相覆盖；后续履约以 Admin 订单台账为准。

## 验证范围

- 原编号幂等、并发投递、乱序更新、同版本冲突、超大报文、缺失/错误/过期签名。
- 未分配池、停用销售、明确账号对应、手工归属保留、跨销售越权、其他国家/OEM 确认门槛。
- 资料补齐、关联同一客户、重复转换、重复客户拦截、源询盘与订单客户一致性。
- 原有价格审核、财务审批、真实收款、实际扣库及客户签收保持完整链路。
- 网站队列持久化、自动分配触发、回执丢失重试、新旧版本交错、租约恢复、无效 200 回执。

本地联调用合成账号、客户、库存及金额；本地通过不代表线上密钥已配置或功能已部署。
