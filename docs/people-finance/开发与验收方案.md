## 现状与复用

- 尚无员工组织档案、班次、签到/请假模块。users 现有岗位用于系统权限，不能代表组织岗位；复用用户 ID，单独配置组织、法人、站点、地点、时区、岗位职能、直属主管和班次。
- finance_documents 已是唯一财务单据账，包含 supplier_bill/payment/allocation、platform_settlement/receipt/allocation、inventory_valuation；finance_rates、finance_period_events 已支持版本汇率及关账快照。新增工作台不另建资金账。
- claim-finance 已有工厂责任赔偿及抵扣来源；新流程不重复计算或抵扣。装箱/采购、运输、仓库和平台结算引用现有业务记录。
- 现有资金账仅管理员/财务可读写，部分岗位 API 还有硬性范围限制。新模块需同时接入导航、系统壳、Node 生产适配鉴权及 API；不能只加按钮。
- 私有文件使用现有 WHOLESALE_FILES 存储绑定，但独立的受权凭证索引及下载 API，不公开对象地址；无绑定时明确不可上传。

## 一期范围与状态

出勤：可配置班次、组织档案、直属主管及人事授权；个人服务端时间签到/签退；班次可跨午夜，休息日不生成人为旷工；单班全日/前半班/后半班请假，主管审批且不得自审、人事复核且不得自审；状态 submitted→manager_approved→approved 或 rejected。保留计划快照、审批人与修订审计；迟到、早退、缺卡/无打卡均为待核对异常，不自动扣薪。支持手机布局。定位、人脸、医疗附件均不采集。跨多日请假、补卡、出勤锁月、人事月汇总签发给财务、工资联动留二期。

财务：费用申请→直属主管审批→总部财务独立复核。能安全支付的一期范围限定为引用既有有效供应商应付的付款申请，严格沿用既有 supplier_payment / supplier_allocation 登记与核销。其余一般费用可保存申请并完成主管流转，来源未建账时明确待补来源，不能伪造已付。薪资与税款不在一期收集明细或支付。

关联应付复核后→待支付→分笔登记实际付款及私有银行凭证→另一财务人员核对银行并按原应付核销→完成。每笔现金只进入 finance_documents 一次，工作台的链接表仅记录来源 ID、凭证 ID 和银行核对事件，不另记资金金额。审批不生成现金流水，不调用银行。不同国家/主体/币种不能相互核销；申请总额、应付余额与已付额均守恒；银行参考号与文件哈希去重。关账沿用既有锁，管理员不能从新接口绕过。

## 权限、数据与界面

员工看本人；主管看直属或显式授权组织（不自审）；人事按授予组织维护班次并复核；国家站点申请人只能在个人组织提交；财务按显式法人/组织范围复核、登记或对账；老板只读汇总需单独授权；管理员管理档案/授权不因此获得审批/支付或薪税权限。授权与岗位分开，后端、列表、导出及文件下载共用校验。财务操作仍须有效财务账号；权限撤回实时生效。

实际实现补充：新增最小系统角色「员工」，仅有人员与费用工作区及岗位手册入口，不授予销售、库存、生产、达人或原资金账权限。人事使用该角色加组织范围的 hr 授权，不借用运营账号。原资金账继续保留既有总部财务权限；新工作台按组织授权收窄，并未声称把原资金账整体改为国家隔离。管理员须根据合同核定历史应付的法人/组织归属后，授权财务才可认领来源。老板只读费用汇总，不返回员工申请、附件或审批记录。

待办并入现有小品提醒，包含主管审批、人事复核、财务复核与付款/核对入口。两页均提供当前授权范围 CSV 导出；按原币展示并保留复核时的月汇率版本。店铺数按组织＋平台＋店铺组合去重，不因 TikTok/Shopee 同名店而合并。待办链接到对应工作区，复杂的单据筛选与大批量分页后续增强。

主数据：组织单元(法人、国家站点、部门、地点、IANA时区)、员工配置、版本班次、授权。单据携带业务日、结算日及银行日，原币始终保存；已核定月汇率与版本由原资金账提供，不用充值估算消耗。新页面使用原站 panel/table/btn 风格及中文/印尼语切换。

## 分期接续，不预设业务或法定规则

1. 广告预算：月预算和周申请、站点/平台/店铺/广告账户/周唯一键、占用释放原子控制；区分批准/充值/消耗/退款，不把全店 GMV 当广告归因。沿用现有日消耗，独立合入跨币种修复后再统一口径。
2. 工厂：装箱行匹配合同价、已结数量及经确认未抵扣的同主体同币种赔偿，沿用 claim-finance 和应付核销；争议挂起。
3. 运输/仓储：由海运负责人发起，按票/仓/账期、重量体积或其他计费基数逐项核验，不在一期猜测费用。
4. 紫鸟/IP：按授权店铺、账号标识、套餐和服务期核单，不存密码。
5. 平台收入：日报→结算→钱包/提现→银行→差异，复用既有账；佣金/退款/内扣广告不能重复费用化，提现不代表利润。
6. 工资/税/办公：办公可申请；薪税独立权限、受限批次及摘要后续实施，不做法定工资税额计算。
7. 人事：多班次排班、补卡与锁月、汇总确认/修订再签发、按事实交财务；各国制度和金额审批线必须由企业确定。
8. 财务修订：已批准申请与关联应付、工作台付款禁止从原资金账旁路修改；一期暂不提供已批准后的撤销、付款冲销或错账重开。生产推广前须补齐独立复核的更正事件及相应核销回退，不能靠删记录修账。未批准申请可撤回或退回，重新提交保留旧记录。

## 验收与发布边界

使用合成数据库验证个人/主管/人事/财务四端，含跨国越权、自审、停用/撤权、重复和并发签到、夜班/半班/休息日、审批不入账、分笔超付、重复银行号/文件、资金账与核销一致、原币汇总、缺汇率未知、关闭账期及凭证下载隔离。相关测试、全部回归、迁移清单、类型检查、Node/Worker 构建依仓库标准执行；受环境阻挡的检查单列。

只添加迁移，不回填真实人员、薪资或财务。保留旧功能入口，导航新增两个独立工作区，默认无人员排班/财务授权。回滚上线前可直接放弃本地分支；若未来部署且已有单据，保留新表和审计，回退应用版本隐藏入口，不删表或改写原资金账；使用已校验备份进行灾难恢复。正式发布须另行授权，本次不执行。
