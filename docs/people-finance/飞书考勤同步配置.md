# 飞书考勤同步配置与操作

本功能接入飞书考勤里的打卡流水与已生效请假。员工在飞书操作一次，本系统按授权范围展示同步事实。它不接管飞书审批，不读取全部待审批、驳回记录，不执行工资扣款，也不把历史本地记录改造成飞书记录。

## 凭据与应用

由维护人员在服务进程可读取的私密文件 `secrets/feishu_credentials.json` 中填写：

```json
{
  "appId": "",
  "appSecret": ""
}
```

文件应仅服务进程及受信任维护人员可读，不提交版本库，不通过前端输入或返回。可用 `LOONGJUMP_FEISHU_CREDENTIALS_FILE` 指定其他私密文件；也支持服务器环境变量 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`。不要将真实值写入命令历史、日志、截图或这份说明。

**当前容器发布默认关闭飞书同步，未配置飞书凭据挂载。** 只把文件放到服务器宿主机目录，容器不会自动读取。正式接通前，维护人员须通过部署配置把私密文件只读挂载到容器，并将 `LOONGJUMP_FEISHU_CREDENTIALS_FILE` 指向容器内路径，或通过部署密钥通道注入上述环境变量；随后重启服务并完成下述连接、员工权限及真实数据验收。配置入口上线不等于飞书已接通。

使用当前企业自己的飞书应用，确认它具备所需的考勤读取权限，且应用可访问的员工范围覆盖拟绑定人员。应用页面能打开、管理员已登录，均不代表 API 已获授权；以连接测试和目标员工数据读取结果为准。

目前支持 `employee_id`、`employee_no` 两种编号类型。选择后必须按该类型填写精确编号，不使用员工姓名、邮箱或 `open_id` 替代，也不自动按同名员工匹配。只要存在任何历史员工绑定，App ID 和编号类型都不能再更换，停用全部绑定也不会解锁，以免混合历史身份。应用及编号类型必须在首次建立映射前核实。

## 管理员首次配置

1. 在「人员与财务 → 出勤管理 → 组织、班次与授权配置」核实内部员工的有效组织和站点归属。飞书绑定不要求本地打卡班次。
2. 展开「飞书连接与员工绑定」，填写与服务器凭据对应的 App ID、员工 ID 类型和设置依据，先保持同步关闭并保存。
3. 点「检查飞书连接」，核对状态是否显示「凭据已验证」。这一步仅表示应用凭据检查通过，不表示所有员工的数据读取权限已经核实，更不表示数据已同步。未通过时先处理服务器凭据或应用配置不一致，不能把测试失败当作数据为空。
4. 在「员工精确绑定」逐一选择内部账号，核对组织，填写飞书编号及绑定依据，保存。一个启用的飞书身份不能同时绑定多个员工；历史身份不能换绑到另一人。
5. 核对无误后勾选「启用飞书同步」，填写设置依据并保存。后台会逐个核验全部映射员工的打卡和请假数据读取权限，通过后才真正启用；任一映射读取失败都需先排查应用权限、人员范围或编号，不跳过后声称已启用。
6. 选择连续 7 天以内的时段，点「同步这个时段」。接受请求后显示「同步进行中」，后台继续处理；页面可见时每 5 秒核对状态，切回页面时立即刷新。看到新的同步成功提示后，再核对「最近成功同步」、目标月份和实际记录。连接测试成功或请求被接受都不代表历史已同步；重复同步核对原记录的修订，不重复制造一份打卡。

管理操作只向后端明确授权的管理员显示。人事、主管按组织和人员权限查看事实；只有汇总权限的人员不因此获得姓名、员工明细或配置入口。

## 自动同步与历史范围

默认每 10 分钟执行一轮自动同步，回看最近 7 天的打卡和请假，同时读取从今天起 30 天内已批准或已撤销的假期。自动任务按实际服务配置运行，连接失败、范围不完整或任务冲突时不能标为成功；以页面显示的成功时间和记录为准。

对于系统已经保存的更早事实，每轮另外挑选一个一周历史窗口进行复核，同一窗口至少间隔 24 小时再复核。历史复核在后台分批推进，不表示全部历史每 10 分钟都已检查一次。

**系统不会自动拉取所有历史。** 首次接入时如需更早的数据，管理员必须按连续最多 7 天逐周手动同步，逐段确认结果。之后已保存的历史才纳入上述分批复核。预定假期的未来范围不等于可以同步未来打卡。

手动同步被接受后，关闭或离开浏览器不取消后台任务。运行中按钮会避免重复提交；状态刷新失败会单独提示，不假称任务失败或成功。重新打开页面后核对运行状态及最近成功时间；失败时先排查原因再重试，不把空列表补成零。

## 员工如何使用

页面显示「已绑定 · 使用飞书」后，新签到和请假统一在飞书考勤办理。本系统不再提供重复的新签到或请假提交。进入「飞书同步记录」，按月份查看同步后的打卡及已生效请假。

若切换前已有未完成的本地班次，可在允许的原班次窗口中点「完成旧班签退」。旧本地请假继续按原主管审批、人事复核流程处理，历史保留。停用同步不删除过去记录。

显示「账号绑定待核对」时，联系管理员核对内部账号、组织和飞书编号。未绑定不会自动认作已同步；未绑定期间的本地流程仍遵循原配置及审批规则。

显示「绑定范围待核对」时，表示已切换飞书来源，但组织或绑定条件发生变化。本地新提交继续关闭以避免重复，管理员核对绑定后再同步，不能把这个状态当作正在正常同步。

## 核对与修正

| 页面情况 | 应如何处理 |
| --- | --- |
| 凭据待验证或凭据待核对 | 管理员核对服务器凭据及 App ID，再测试；凭据通过后，启用环节仍会逐个核验全部映射员工的数据读取权限。 |
| 凭据已验证，没有同步成功时间 | 凭据检查、映射权限核验和数据同步分别处理；完成启用后手动同步目标时段并核对结果。 |
| 当前月份没有记录 | 核对月份、绑定、同步窗口和飞书来源；不推算缺勤或零请假。 |
| 同步失败 | 保留已有记录，核对页面错误及上次成功时间，修复后重试目标时段，不补造完成状态。 |
| 来源暂未找到 | 原记录保留并标记待核对，不直接判定请假已撤销。回飞书核对后重新同步。 |
| 员工调岗或编号填错 | 停用原映射并保留原因，然后按当前有效组织新建正确映射；原身份及组织不覆写。 |
| 恢复同一员工、同一编号和同一组织 | 从原绑定重新启用，不能新建一份重复映射；原同步历史沿原绑定保留。 |
| 需要变更编号类型 | 尚无任何历史映射时可核实后修改并重新检查凭据；已有历史映射时禁止更改，停用全部映射也不能解锁。联系系统维护人员评估独立迁移，不能覆盖既有身份。 |

界面时间按当前设备时区显示，月份严格按飞书来源工作日期筛选。条数是日行记录数，不是请假次数或人数；同一多日假期可能有多条日行，跨月假期在相应来源日行中仍显示完整起止时间。已知时长与未知时长分别保留；缺失记录不补成零。飞书来源的更正应先在飞书处理，再同步核对。本系统不承诺飞书尚未生效的审批过程已经同步，也不自动核算薪资。

## 验收建议

先用经确认的少量员工检查：精确绑定、连接失败提示、已生效请假与打卡读取、重复同步不重复、来源修订及缺失提示、本人/主管/人事/汇总权限隔离。再核对切换后新本地提交被阻止，而旧班签退和旧请假仍可收尾。未通过真实应用与目标员工数据验证前，不把本地测试结果当作生产接通。
