## 主数据和状态

1. 建立组织单元：法人、国家站点、部门、工作地点及 IANA 时区。已有单元的法人/站点/时区不覆写，转组织用新单元。
2. 建立班次：开始/结束、工作星期、签到和签退宽限。结束早于开始表示次日；历史打卡/请假保留当时计划，不随新班次改变。
3. 复用员工账号，关联组织岗位、直属主管及班次。系统角色只控制系统能力，不替代真实组织岗位。
4. 显式授予组织范围的 manager、hr、finance 或 executive；财务授权还必须对应有效财务系统角色。
5. 历史应付由管理员按合同核实组织/法人，保存依据后锁定。未核定来源不显示给组织财务，不按供应商名称猜法人。

请假状态：`submitted → manager_approved → approved`；可退回，未批准前可本人撤回。主管与人事复核不允许同一人兼任本单两步。单班全班/前半班/后半班，两个已批半班可合为全班；休息日不伪造工作日请假或旷工。签到时间只能取服务器，跨午夜按原班归属。未配置历史班次的日期不推算历史旷工。

费用状态：`submitted → manager_approved → approved → complete`；未批准前可退回/撤回。财务复核必须匹配同法人组织、站点、平台和币种的有效已核对应付；审批仅占用余额，不写现金。分笔实付登记写原 `supplier_payment`，另一财务核对后写原 `supplier_allocation`；全额核销才完成。付款链接表不存第二份金额。

缺来源、缺汇率、未支付和未核销分别保留真实状态。汇率缺失时人民币金额未知，不能显示已折算的零。原币按法人/站点/币种分组，店铺数按组织/平台/店铺去重。

## 一期未做，以及为什么

- 补卡、跨多日请假、复杂轮班、出勤锁月、人事签发月报给财务、工资联动：需独立修订与签发流程；一期不按异常扣薪。
- 已批申请撤销、错账/付款冲销：目前阻止从旧台账直接改写。必须在广泛生产使用前增加独立审核的更正链条，一期不能靠删单修账。
- 跨已关账业务期付款：一期对原申请/结算期/来源应付期已关闭的单据保守阻止继续付款，即使新的银行日处于开放期，也暂不开放。后续必须把新期间付款事件与已封存申请快照分开，验证期初应付和新期核销守恒后再启用；不能把反关账当作日常付款步骤。因此这一版是本地一期验收版本，不应直接推广为完整财务生产系统。
- 广告月额度/周占用/充值/实耗/归因 ROAS：一期只有预算意向，不能直接当费用或付款。跨币种修复保留独立。
- 工厂装箱逐行合同结算、运输计费、五国仓费、紫鸟/IP 账期明细：一期只有分类和发起岗位限制，不声称已完成这些专用核单模型。
- 一般办公/运输等来源尚未进入原应付账时，申请只能停在待补来源；不造第二套应付或伪造支付完成。
- 薪资/税款：不收集明细、不计算、不支付；需专属权限和受限批次后再开放。
- 平台钱包/提现/到账全自动匹配、本期经营分析：保留原系统已有账与入口，本次未重建或承诺自动完成。
- 大批量历史分页、细化单据定位、按量性能基准、Worker 云端实测：本次未做生产负载或云端访问；已有本地 Node 真登录和 Worker 构建验收。
