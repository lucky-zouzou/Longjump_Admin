# LOONG JUMP 业务流程与修复清单

## 业务口径

印尼线下批发流程：销售建客户并提交订单 → 财务独立审批并选择供应链负责人（管理员可协助）→ 预留两平台库存 → 财务导出仓库备货单并人工通知仓库 → 供应链打包并提交物流单号或有效出库影像 → 确认实际交付后扣减库存 → 完成发货归档。申请人或本单销售负责人不能自审。

新订单必须选择寄售、现金销售或特价清仓现金销售，同单混合业务需拆单。现金两类均先款后货；特价清仓及寄售审批须填写价格与结算依据。历史订单保留未分类标记和原结算口径，历史待审批订单可核实后补充类型，已审批历史订单不自动重分类。

现金类及历史订单按实际 SKU 出库件数乘订单成交价计入 IDR 销售额。寄售出库只表示货物交给客户，财务依据客户销售对账凭证确认已售数量后才形成销售额和应收，再登记实际回款与开票。确认已售不再次扣库存，可在开放月份追加负数冲正，禁止超出客户处未售数量或可冲正数量。发货完成、回款结清和开票是独立状态。

财务／管理员可导出审批后尚未发出的备货明细，指定供应链也可导出本人负责订单。导出前核对订单版本；分批发货后仅导出余量。备货单不代表付款或实际发货，导出不扣库，也不会自动给仓库发消息。

“导出本月出库明细（模板）”按实际出库日期逐次列示，以用户的9月模板A:Q字段顺序为基础，区分正常销售／商品清仓及寄售／现款，右侧补充业务类型、原订单号、版本、仓库与联系资料。商品颜色、尺寸及业务代码来自录入/导入的订单快照，未知显示未维护；不从SKU猜测。模板中重复的客户代码统一取订单快照，原9月数据不导入系统。

寄售退货须明确本次已确认售出数量与未售部分，仅已售部分冲减销售和应收；仓库实收仍按全部退回件数恢复原渠道库存或隔离库存。退回货值、冲减销售金额及实际退款分列。所有新增表单、提示和导出标题支持中文／印尼语，业务数据原文和IDR数值不随语言改变。

现阶段按 TikTok／Shopee 可用库存均分预留和扣减；奇数余件与单边不足按现有规则分配，总扣减始终等于实际出库数。其他国家库存不受影响。虚拟线下库位按原业务安排留待后续启用，本次没有擅自迁移库存。

## 8 项审查缺陷

| 编号 | 修复后的行为 | 验证 |
|---|---|---|
| A01 采购负责人错误 | 月度审批和新品量产指定启用中的供应链账号；管理员可重新指派采购负责人，记录原因 | 供应链接单成功；管理员不能被当作供应链指派 |
| A02 隔离退货无法处理 | 依据退货原渠道逐笔质检放行或报损；运输隔离仍按运输来源处理 | 分次放行、报损、数量守恒、禁止重复超量 |
| A03 合并付款无法核销多单 | 独立银行收款单一次登记，同客户多订单分配；保留未分配预收 | 一笔 500,000 IDR 核销两单，不重复统计银行到账 |
| A04 错误收款不能冲正 | 保留原始记录，追加回款／退款冲正；银行核销可撤销回未分配余额 | 应收恢复、原记录保留、重复冲正拒绝 |
| A05 审批与驳回并发冲突 | 事务内验证待审批状态和版本，执行单与审批状态同批提交 | 控制并发交错，仅一个请求成功 |
| A06 旧发运并发超产量 | 新旧发运通路共同受数据库数量保护 | 产量 10 件并发两批各 7 件，仅一批成功 |
| A07 零需求无法提交 | 明确选择“本月无需备货”并填写说明，计入站点完整度 | 五站双渠道全零可完成审批，不生成采购单 |
| A08 样品换版沿用旧确认 | 开发和运营确认绑定样品版本，换版后重新签认；重新定价须重新测算 | V1 确认不能放行 V2；新财务轮次阻止旧测算 |

## 补齐的管理能力

- **月度计划变更**：原计划、变更后明细、差异和原因保存，另一位管理员审批。已下单／生产部分保留；仅未执行草稿被撤销重建，不能将新总量低于已执行数量。相同系列、供应商但不同工厂可分别下单。涉及 SKU 有负库存、预留短缺或异常库存分量时，审批事务会阻止通过，须先核对差异。
- **客户维护与交接**：资料修改、停用、同名同电话重复检查、管理员交接。历史订单保留当时客户资料和原销售贡献，服务权限交给接手人员。
- **财务关账**：已结束月份可关账，保存不可随随后业务变动的月末快照；禁止补录已关账截止日以前的订单、出库、退货和财务流水。误登记在开放月份追加冲正。管理员按倒序反关账。
- **对账导出**：全部订单、月度余额、SKU 出库、收款退款核销、开票、退货、说明；存在银行收款单时增加银行收款余额和实际银行收支表。客户、币种、结算状态、结算金额和流水引用均可追踪。
- **中／印尼语**：线下新增加的客户维护、银行核销、冲正、关账界面与错误提示和导出字段纳入语言切换。切换只改显示，不改变金额、客户原文或 SKU。
- **预测升级**：滚动 7／21／56 天加权，按 SKU＋国家＋渠道维护供应商及运输方式参数。纳入实际交期、安全天数、活动、季节、生命周期、断货、退货、异常爆量、MOQ、整箱和分配到 SKU 的产能／预算／仓容上限。
- **预测复盘**：人工追加且无历史销量的 SKU 明确记录零建议及数据不足，不漏存运营调整。提交时保存系统建议、运营调整、预测月销量和模型输入；审批后写最终批准量；按月对比实际净销量，展示加权准确率和偏差。无实际销量时不虚构准确率；未结束月份展示进行中数据。
- **全站自查**：总览检查采购指派、审批与执行单冲突、发运超量、样品版本、银行核销余额、隔离库存来源、线下预留对账、关账快照、重复客户和渠道分配数量。
- **正式部署与恢复**：自有服务器公司账号、持久数据库、迁移、文件存储、每日备份、哈希校验和恢复程序。

## 使用中的关键区别

1. 银行实际到账与订单核销分开。把银行流水分配给两张订单，不等于银行收到两笔钱。
2. 现金类及历史订单已发货即确认销售；寄售须确认客户已售后才确认销售和应收。只有已确认销售的退货部分冲减销售；退款是独立的实际资金动作。
3. 运输隔离品放行进入待上架；线下退货经过质检确认后回到原渠道可售库存。
4. 客户交接不把历史销售业绩算给接手人员。
5. 计划变更保留已执行订单，不自动撤销已经生产或运输的货物。
6. 完整备份含文件原件；数据库 JSON 与源码 ZIP 均不能替代业务数据完整备份。

## 本次范围之外

对外 B2B 营销询盘网站、未来线下虚拟仓位、各平台实时订单接口和多实例数据库扩容不属于本次审查修复。现有线下端口、月度计划、预测、生产、运输、财务和新品模块按本清单完成修复与补齐。
