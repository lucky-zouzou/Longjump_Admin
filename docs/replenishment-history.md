# 历史补货计划

## 使用入口

补货驾驶舱及月度计划页面顶部均提供“历史补货计划”。点击“查看上月计划”默认查看上一个北京时间自然月；“查看历史月份”可切换至已保存的月份、本月或上月。

- 运营：仅查看本人当前负责的站点、渠道，不以提交人 ID 限制，交接岗位后仍可查看该范围历史。
- 管理员、供应链、运营主管：查看全部计划，可按站点和渠道筛选。
- 不新增工厂、财务、海运或销售岗位的计划访问权限，不改变原有 Excel 导出权限。

页面显示运营提交数量、审批计划数量、SKU 种类数、月度计划状态、提交人及时间、版本、无需备货说明。SKU 明细可搜索商品、SKU 或调整原因，每页 30 条；上方汇总按月份、站点和渠道统计，关键词只筛选明细。

## 数据口径

`GET /api/replenishment-history?month=YYYY-MM&site=...&channel=...` 是只读接口，使用现有登录认证并禁止缓存。没有数据库迁移或写入操作。

- 提交量来自 `monthly_submissions.items_json`，与保存的 `total_qty` 交叉校验；商品名及原因采用提交时的保存值。
- 计划量来自该月 `approval_requests` 的 `monthly_plan` 分配明细，不调用实时预测、库存或销量。只有 `approved` 才标记“已批准计划量”，其余状态显示“送审计划量”。
- 已批准计划可能包含后续批准的变更，不能把这一数量当成最初提交量。两个数量分列展示，差异使用强调色。
- 对审批新增、删除的 SKU 取提交与计划分配的并集；已存在的提交/计划中未列出的 SKU 数量为 0。没有对应提交或审批时显示“—”，不当作零需求。
- “已确认无需备货”保留确认说明；缺报与无需备货分开呈现。上月无记录时明确提示，不自动切换到更早有记录的月份。
- 历史查询直接按月访问保存记录，不受工作区最近 100 条审批展示范围影响。运营接口只返回本人范围内的 SKU 分配和审批状态，不返回原始采购条款、价格或其他站点的分配。

## 历史边界

现有系统对同一个月、站点、渠道重新提交时覆盖明细并递增版本。本功能展示该月**最近保存的提交**及**当前保存的审批版本**，不伪造每次修改前的完整明细，也不恢复已清理的测试数据。无需新增快照便可查阅当前数据库中已留存的历史月份。

## 验证

- 新增 8 项历史查询测试：跨年/北京时间默认月份、提交与批准量差异、角色与站点隔离、零需求/缺报、超过 100 条审批的旧月份、审批状态、增删 SKU、坏数据报错及只读性。
- HTTP 集成测试覆盖实际公司登录、所有岗位、跨站越权、未登录、无缓存及禁止 POST。
- 本轮 483 项测试通过；TypeScript、新增代码 ESLint、Node 和 Cloudflare 构建通过。
- 合成数据预览核验管理员与运营两种视图、月份切换、筛选、SKU 搜索，以及 390px 手机布局。未读取或修改正式业务数据。
