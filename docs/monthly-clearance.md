# 月度清仓：业务与验收说明

开发分支：`codex/monthly-clearance`。本次仅本地开发与验证，未发布，未读取或修改正式清仓业务数据。

## 已确认口径

- 五站分别制定月度清仓计划，执行明细按站点、TikTok／Shopee、SKU分配唯一运营负责人。同一月份和执行范围不重复建单。
- 财务允许的25%／30%是清仓让利测算，不是采购成本下降。保留真实到仓成本及其版本；截图未提供的售价公式不推断。
- 建议售价、财务批准售价、执行底价分开。让利比例可编辑，不自动把原成本减记；最终价格由财务核定、管理员批准。
- 实际贡献利润＝实际销售额－真实商品成本－广告－平台－履约－退款及售后净成本－其他直接费用。成交额已含折扣，不再重复扣让利。
- 销量来自负责期间每日导入数据，代表该期间业绩，不等于活动带来的新增销量。已导入部分可展示，但缺少完整日报时不能给出确定剩余目标或利润。
- 当前库存读取实时账面减预留，不用“期初减销量”冒充当前库存，避免遗漏入仓、调拨、线下出库等变动。

## 使用流程

1. **运营／管理员／运营主管：** 在“月度清仓”选月份，创建SKU计划。选择站点、平台和负责人，填写数量目标、建议价、问题依据及动作方案。草稿可修改、取消和重新送审。
2. **财务：** 核实完整到仓成本和本月固定汇率，填写计划售价、执行底价、让利比例、广告及其他直接支持预算、可接受净亏损上限及凭据。
3. **管理员：** 独立审核。成本或汇率在核定后修订，必须先重新核定。审核不改平台价格或库存。
4. **负责人：** 在平台执行后登记实际售价、执行记录编号／链接及说明。开始记录时保存可售库存快照。日常记录素材、投放、链接、直播、组合促销、品质整改或调价等动作。
5. **财务支持：** 记录支持措施及依据；记录本身不代表付款。实际费用仍只记入每日成本台账。
6. **每7天复盘：** 从实际开始日计算，月底不足7天单列短周期。自动读取销量、库存、原币及人民币利润、费用完整度。可决定继续、调整或建议停止；建议停止不会伪造平台已停止。
7. **财务结案：** 运营登记停止凭据，等待末日销售结束，核清全部每日费用并完成全部周期复盘后结案。成本修订保留旧凭据，使复盘显示依据变化；清仓页面修订已结案费用会重新打开跟进。

## 核算与责任控制

- 共用 `business_action_finance_days` 逐日成本台账。新增一天只补该日；退款、销售或成本来源修订后核对变化日期。原有台账未明确其他直接费用的日期，在清仓统计中先标待核实。
- 店铺广告分配总额受已有规则校验，避免将店铺总费重复计入每个SKU。
- 原币预算是审批边界。预算总览按批准时汇率换算；实际人民币利润使用财务本月固定汇率。缺汇率不默认为1，缺费用不默认为0。
- 支持预算包含已核实广告及其他直接费用；净亏损上限与支持预算分开监控。超限仅提示人工处理，不自动停止平台活动。
- 管理员／主管可以交接负责人；执行中计划从站点当地次日生效，历史贡献保留原负责人。每笔销售只按当天负责人统计一次。
- 已批准／执行中的原优惠申请与同范围清仓计划防重叠，防止两套活动重复归因。
- 工厂、海运、供应链及线下销售不增加本模块财务查看权限。运营仅看本人站点／平台；财务、管理员及主管查看五站。
- 所有保存具备请求幂等、版本及来源校验、维护锁保护。计划不自动改价、投广告、下采购或扣库存。

## 日报与库存联动（2026-11-04）

- 五站均覆盖 TikTok 与 Shopee。清仓计划按站点、平台及系统 SKU 精确关联销售日报和现有库存份额，不将站点总库存复制到两个平台。
- 销售导入服务在一个事务中写入日报、扣减库存并记录库存流水。清仓只读这些结果；创建、审批、刷新清仓计划不会再次扣库。改文件名、批次号或并发重复推送仍由原导入约束阻止。
- 看板增加“日报 → 清仓进度 → 实时库存”：期间已导入销量、销售净扣库、当前可售库存、按已导入销量距目标还差数量和完成率。
- 进度按实际开始日至停止日／计划末日的经营日期统计，含当地今天已导入数量；当天未结束标“今日进行中”。缺报和费用文件不会视为零销量，完整日报没有该 SKU 才能认定零销量。财务核算及7天复盘仍截止当地昨日。
- 销售修订保留旧批次冲销和新批次扣库，清仓使用修订后有效销量。销售冲销恢复库存；退款金额本身不意味着退货重新入库。
- 当前库存直接读取库存台账：账面减预留。到仓、调拨、盘点、线下出库可能同时改变库存，不能简单用开始库存减清仓销量推算。
- 每日核对展示原扣库、冲销恢复、净扣库；可展开原文件、平台批次、系统导入编号及库存流水编号。按每个批次核对数量，发现不一致时不补扣、不给确定完成率，并阻止财务结案，交人工核对。
- 月度导出增加“销售与库存联动”“每日销量扣库核对”“销售扣库批次凭据”三张表，共9张。未知数量保留空白，原财务口径与实时进度口径分别说明。
- 新增13项验证，其中12项从真实导入／修订／冲销服务串到清仓读取，另1项验证库存流水异常阻止结案。完整套件共537项：536项在默认环境通过，本机 HTTP 测试因监听权限受限，使用允许的本地监听权限重跑通过；类型检查、Node和Cloudflare构建通过。
- 11月真实清仓文件及双平台待分配数据保留在本地私有工作目录；本次没有将未分配负责人、数量、执行日期的候选项擅自变为执行中的正式计划。预览只用合成数据，旧预览保存在 `work/clearance-preview-before-stock-20261104`。

## 自动零动销商品池（2026-11-04）

- 月度清仓页顶部直接读取五站当前库存与销售，不依赖是否已创建计划。管理员、财务、运营主管按站点汇总，同一 SKU 合并 TikTok／Shopee 后计一次；运营仅查看、申请其已有权限内的站点／平台。默认选中印尼，运营默认自己的站点。
- 零销量窗口按各站当地昨日向前30个完整自然日。缺报、部分日报、费用文件、跨SKU重叠销售均不能算完整日。全站零销量需要两个平台的日报均完整；仅一个平台没有销量时标“部分平台零销量”。历史连续有货证据不足时标“30天零销量 · 有货待核实”，不冒充确认滞销。
- 商品展示当前可售（账面减预留）、站点有效版本成本（CNY/件）、成本范围与版本。缺成本不填0；缺库存或预留异常不当作0库存。站点卡片的库存及已知成本货值只汇总零销量候选，不代表该站全部库存；有成本缺项时显示缺项数量。
- 今日已导入正销量会显示“今日恢复动销”，不再允许从零动销入口新申请该平台促销。用户仍可根据业务诊断创建普通清仓计划。刷新、进入页面及每分钟可见页面更新均重新读取，不在读取时扣库。
- 展开平台可核对负责人、库存、7天日报完整度、今日已导入量、缺报日期及每日销售扣库流水；原导入、修订、冲销记录全部沿用现有台账。某天完整日报缺该SKU行为零销量；今日或缺报时未知销量显示待核实。恢复库存仅根据实际冲销／库存业务，不把退款金额自动视为退货入库。
- “申请促销价”带入站点、平台、SKU、库存目标及零销量依据，售价由运营按站点本币填写，不把人民币成本直接当本币价格。保存时服务器再次核对完整日报、库存及销售流水；目标不得超过当时可售库存。来源窗口、成本版本、连续有货核实状态和快照时间保留在计划中。
- 保存为草稿，继续既有“运营送审→财务核价和预算→管理员审批→运营平台执行登记→每日跟踪→每7天复盘→财务结案”流程。成本不完整可先保留草稿，财务核价仍须完整到仓成本及有效月度汇率。系统不会自动改价、投放广告或额外扣库。
- 已有本月计划、跨月执行中计划及未结束的旧优惠申请均显示原记录入口，不另建相同活动。同一申请重试返回原结果，并发销售／成本／库存修改由事务来源版本阻止旧依据写入。
- “导出当前范围”导出当前站点、状态、SKU筛选结果，每个平台分别列成本、库存、销量、缺报日期及已有计划。未知金额／数量保留空白，不与既有9张月度复盘表混淆。

- 财务先核价与批准支持范围，执行后只提示销售依据已齐但费用新增或修订的日期。销售依据缺失先交运营；已确认日期继续复用共享成本台账。已核实支持费用超预算、完整核算后的净亏损超上限优先提示财务与运营，未核齐费用不冒充零亏损。
- 管理员处理审批与库存异常，也可督办运营、财务的逾期事项。过期未执行计划提示取消后重新安排，不让运营卡在无法执行的按钮。页面“建议处理日”来自计划开始／结束、日报次日或复盘次日，是系统建议，不冒充人工约定期限。
- 角色待办可见不等于获得对方操作权限；财务和管理员仍各自保留审批边界。运营按当天生效的负责人认定，不因明日交接把今天责任转走；财务／管理员显示岗位，不虚构已指定的个人。
- SKU详情同时展示最近运营动作、财务支持意见、下一复盘区间、执行时库存、实时可售及净变化。库存净变化包括入仓、调拨、盘点、预留和其他出库，不等于清仓销量。每天在一行对照销量、净扣库、销售额、已核齐贡献利润；未知值保留“待核实”。
- 停止优惠、出现销量、目标售出或可售归零均不会自动结案。财务结案继续要求停止凭据、完整费用、有效复盘及扣库一致。月度导出仍为9张表，主表增加当前生效负责人、库存净变化、最近动作、下次复盘和三方待办。

## 每日零动销提醒：运营、财务与管理（2026-11-04）

- 总览增加“每日零动销预警”，不被普通待办前4条折叠；月度清仓导航计入相同站点提醒。运营只收到账号绑定站点／平台，财务、管理员及运营主管收到五站汇总，保持既有数据与操作权限。
