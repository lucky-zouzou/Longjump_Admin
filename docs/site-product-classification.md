# 站点商品分类

入口：成本利润透明 → 商品成本与动销 → 动销看板／分类规则。每日经营行动单中的商品健康全景和 SKU 图标使用相同站点结果。

## 统计与初始参数

每个国家、每个 SKU 只有一条分类。合并 TikTok 和 Shopee 的正向销售数量，以及两边独立分配库存扣除预留后的可售数量。成本按站点 SKU 匹配一次；不改变底层销售、库存或渠道业务记录。

| 站点 | 28天爆款日均 ≥ | 28天热卖日均 ≥ | 7天爆款日均 ≥ | 7天热卖日均 ≥ |
| --- | ---: | ---: | ---: | ---: |
| 印尼 | 18 | 3 | 18 | 3 |
| 泰国 | 7 | 2 | 7 | 2 |
| 马来西亚 | 4 | 1.5 | 4 | 1.5 |
| 菲律宾 | 5 | 1.5 | 5 | 1.5 |
| 越南 | 3 | 2 | 3 | 2 |

单位为件／天。热卖的上限为同周期爆款阈值，不重复计数。两个周期独立判断；同时爆款显示“持续爆款”，仅7天爆款显示“近期起量”，28天爆款但7天未达显示“近期放缓”。四个周期榜单有交集，数量不可相加。

以上是按已核对站点销量分布制定的试运行参数，不是市场统一标准；缺报站点及小样本站点应补齐证据后复核。不会每天自动按百分位重设阈值。管理员可逐站调整并填写依据，保存新版本。财务、运营可读不可改规则。

## 销售分级与健康分类

- 销售分级：只在该周期双平台日报都完整时确认；7天完整、较早日期缺报时，仍可确认7天榜单。未达热卖显示“未达热卖”或“零销量”，不据此推断库存健康。
- 四类健康：以28天分级为基础，还需已核实库存、上架日期及观察期。默认观察至少28天。
- 滞销：可售大于0，连续有货7天零销量，或28天日均低于0.5件且库存覆盖至少90天。须有连续有货证据。满足滞销条件时优先标记，周期销量分级仍单独保留。
- 同日一个渠道的完整日报不能补全另一个渠道的缺报。先各渠道判断重复批次／部分日报，再取完整日期交集。不得把两渠道同SKU合法销售误判为重复。
- 任一渠道库存记录缺失、负库存、预留超过账面或数量溢出，站点可售与库存占用标为待核实，不用另一边库存抵消异常。
- 站点首次上架采用已核实渠道上架日期的最早日期。每天至少一个渠道有可信连续在售有货证据，才认为站点当天有货；当前库存不能证明历史持续有货。
- 截至各站点当地昨日，不含当天。缺报不当作零，销量高不等于盈利；系统不自动改价、改广告或采购。

## 权限与版本兼容

运营仅可获取自己原有 SKU 范围的本站合并分类、数量与成本；不返回其他站点、仅属于另一平台的 SKU、原始跨渠道金额或广告数据。日报证据核验及渠道财务行动仍沿用原权限。

规则使用现有 `product_class_rules` 版本表，新增 JSON 结构 `scope: site`、`sites`、`reviewedSites`。旧全局版本保留作审计，不再把旧全局阈值应用到站点汇总；未保存站点使用上表初始值。编辑采用版本冲突保护，保存某站点不覆盖其他站点。无数据库结构迁移或业务数据回写。

新规则 JSON 同时保留旧全局字段供回滚版本读取；当前版本只采用站点映射。回滚到旧代码会恢复旧的渠道分类逻辑，不会继续应用站点规则。旧版若再次写入全局规则，重新升级时须复核站点参数；历史站点版本仍可追溯。

验证覆盖：跨平台汇总、国家独立阈值、两个周期独立、缺报／重叠批次、库存异常、连续有货、时区边界、角色隔离、版本冲突、备份恢复；界面测试使用独立合成数据。
