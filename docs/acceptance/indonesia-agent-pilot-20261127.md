# 印尼 TikTok 单店 Agent 试运行

状态：本地实现与合成数据验收；尚未发布、未启用真实店铺。

## 试点需要的信息

- 唯一店铺（使用现有达人店铺编号），对应有效运营与 BD。
- 1–30 个重点 SKU、负责核对到仓的供应链同事。
- 核对旧系统「印尼 / TikTok」经营数据是否只属于这家店。旧销售、广告、库存、售后表没有店铺编号，不能靠录入人猜测店铺。
- 默认北京时间每天 10:00，周一同一时间生成上周报告；可调整时间。业务日使用 Asia/Jakarta。

## 经营巡检

每天只读原业务台账。按问题稳定编号保留一条待办，显示证据、影响、负责人、复查日期。

| 检查 | 依据 | 缺失处理 |
|---|---|---|
| 缺报 | 当地已结束的近7天完整日报、导入冲销及重叠校验 | 部分日报、未报不算零 |
| 重点 SKU | 近7天完整销量日均、库存减预留、已登记在途及 ETA | 缺销售/库存/交期则待核实；待上架和隔离不算可售 |
| 广告实际消耗 | 昨日实耗与前7日同币种日均 | 不用预算、充值代替实耗；缺日或冲突不输出正常结论 |
| 退款登记异常 | 已提交售后中的退款订单去重，默认近7日3单提醒 | 人工台账不是平台全量退款，不能计算真实退款率 |

库存默认3天提醒，广告默认增加50%提醒。阈值是试点提醒规则，不是自动执行权限。
库存预测是维持近7日日均的情景，没有默认推测大促增长。到仓按登记日期保守处理，未知或逾期 ETA 不抵消缺货风险。
店铺归属未确认、出现第二家店、运营或店铺版本变化时，停止单店经营结论并交运营核实归属。

## 达人履约

现有样品单 → 全部实际发出批次签收 → 合同有效交片日期已过 → 没有关联有效视频 → 一条 BD 待办及印尼语草稿。

- BD 核对后确认草稿，再复制自行发送；系统没有发信接口。
- 确认/复制时重新读取视频、协议、负责人；视频已关联就拒绝旧草稿。
- 每分钟和读取待办时重新检查关联；视频一关联即停止催拍。内容验收仍在原流程处理。
- 未签收、无视频义务、合作暂停/取消不催拍；缺日期或负责人仅提示核实。
- 同一寄样内容事项在「我的待办」以 Agent 提醒替换旧泛化提醒，签收、财务等不同事项不合并。
- 负责人改派后重新打开任务、清除原确认；原跟进说明留在事件记录。

## 周报与跟进

- 每位 Agent 最多列3件当前最值得决策的事，并列上周已跟进、证据解除、再次触发记录。
- 明确区分「当前决策快照截至何时」与「上周整改 / 履约日期」，归档周报不被后续手动巡检覆盖。
- 达人交片率以到期且已签收的合作轮次为分母，足量视频关联才计交片；与验收通过分开。
- 出单是成熟7/30天观察窗口的累计归因订单，不叠加窗口，不冒充自然周销量。
- 样品成本和寄样运费分列，按财务核定业务日及汇率；缺成本/汇率不算零，不生成销售收入。
- BD 仅看本人负责轮次的周报；费用金额仅管理员、总部财务可见。
- 只有原始证据明确解除才自动关闭。人工跟进不能一键宣称问题已消失。

## 岗位与数据边界

入口：日常工作 → 单店 Agent 试运行；负责人原有「我的待办」可直接定位。
管理员配置；运营主管可启动巡检；运营查看本店经营；供应链查看分配给自己的事项；BD查看本人履约；财务核对成本。
暂停试点停止定时运行和草稿确认/复制，不删除已留存证据。
新增配置、任务、事件、报告和运行锁均纳入完整备份，并受维护锁约束。来源版本变化或并发竞争时中断保存，不把读取失败标记为成功。

## 验收方法

- 业务单元与集成：范围隔离、缺失不计零、重复巡检去重、显式解除、改派重开、BD 草稿确认和复制、视频关联撤回、本人周报与财务字段隔离。
- 定时：默认关闭、指定时间后运行、错过周一补跑、配置变更后重算日报、周报固定归档。
- 生产构建真实 HTTP 登录：BD 可读 Agent，但不能配置/启动；其他站点、无关 BD、工厂拒绝访问；原业务权限继续回归。
- 备份恢复：修复新配置默认行与归档恢复冲突，复测完整备份与附件链。
- 合成 UI：管理员经营卡片、BD 跟进和草稿、岗位待办定位及窄屏布局。合成数据库位于 work/agent-pilot-preview，不进入源码。
- 回归另修复了印尼跨午夜达人核算日期按 UTC 误拒绝的问题；登录限速测试固定逻辑时间，避免本机休眠跨过15分钟窗口导致误报。
