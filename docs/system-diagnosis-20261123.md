## 结论

系统已有销售、库存、备货、生产、运输、到仓、售后和财务的基础链路。当前最影响管理体验的，是自然语言查询覆盖不足，以及业务资料迟报、缺报和责任人未落定；扩大模型能力不能代替这些事实。

小品的问题已在正式站复现：询问「昨天各站销售怎么样？帮我总结一下，有什么需要跟进？」后，返回岗位手册未命中及模型暂未响应。代码核对确认：既有销售经营问答主要支持自然月，另一些销量问法只跳转销售台账；缺少每日经营简报读取器。不是销售库没有接口，也不是该次请求一直在等数据。

## 本地完成的修复

1. **直接问每日销售结果。** 支持昨日、今日、前日、近7天、近30天、本周、上周，以及连续31天以内的明确日期。默认未给日期的销售简报使用各站当地昨日，回答注明实际范围。
2. **结果、依据、跟进连起来。** 回答已报销售件数、已知人民币销售额、广告费、同口径前期比较；展开可看每站平台的完整度、缺报日期、销量前列SKU、原币与汇率依据。
3. **连续追问能保留范围。** 「那印尼呢」「只看TK」「那11月22日呢」「为什么下滑」「我该找谁」按原期间继续查询。修正界面快捷追问未传业务上下文的问题，月度、备货、生产的原有上下文也一起保留。
4. **每次读事实。** 与月度目标复用同一份销售、广告费、完整日报查询及计算规则，撤销数据剔除、店铺广告费覆盖SKU广告费。不会把实时销量存成可反复使用的知识答案。
5. **缺报不作零，权限不扩大。** 运营只读本站平台；管理员、财务、运营主管按各自可见范围读取；其他岗位不给出销售金额简报。今天未结束不与昨日全天计算涨跌。两期不完整时不做全局排名和涨跌判断。
6. **降低对外部服务的依赖。** 直接读取本地业务库和有效参考汇率缓存，不需GPT额度，不等外部模型或汇率服务。外币缺汇率保留原币待核，人民币参考值不冒充财务结算或利润。
7. **增加明确入口。** 小品首页增加「昨天卖得怎么样？」；保持原有岗位手册、经营比较和待办入口。

本功能读取运营已导入的数据，并不自动向TikTok/Shopee拉取平台报表。分销、单SKU逐日金额、订单数、转化率不混进这份摘要；不支持的查询明确说明，不能拿全店数据替代。

## 各岗位进一步优化顺序

| 优先级 | 岗位/环节 | 建议与验收方式 |
| --- | --- | --- |
| P0 | 运营与管理 | 每天明确日报齐备状态、负责运营、提交期限；先处理最近日期缺口。验收：完整日报覆盖率上升，漏报按负责人可追踪，真实零销量需明确确认 |
| P0 | 供应链/工厂/海运 | 把已批订单、实际完工、实发、ETA、到仓与上架逐段核对。过期ETA需原因、负责人和下一次跟进时间。验收：单个站点月度计划可以沿原单逐项对账 |
| P0 | 管理层/财务 | 统一将“已报销售额”“财务已核利润”“实际到账”“预测建议”明确分开。验收：任一结果都能看到期间、币种、完整度和原台账，不把缺口补零 |
| P1 | 小品问答 | 建立岗位真实问法清单，记录未命中类型；优先补高频只读查询。将通过验证的问法加入回归。不要自动把未经核验的自由生成答案变成经营规则 |
| P1 | 管理与运营 | 将简报里的异常关联现有行动单：责任人、期限、处理证据、下一次复查。自动生成前做同问题去重，避免每天新增同一待办；本轮只读提示，不擅自分配任务 |
| P1 | 备货计划 | 登记活动日期、站点、平台、预计增量与依据，结合工厂承诺及运输到仓时间；逐步对照预测与实际误差。未确认的大促不自动当作确定需求 |
| P1 | 财务 | 推进费用凭据、关联销售、汇率、核销与月结齐备率；参考销售额可用于观察，正式利润必须沿用财务证据和关账版本 |
| P1 | 内容/达人 | 持续检查站点+Video ID关联覆盖，区分“报表已导入”与“已关联内部拍摄贡献”；缺关联不自动归功于某岗位 |
| P1 | 分销/售后 | 完整检查申请审批→账号激活→订单→凭证→财务核销→售后复查；实际素材存储仍需配置后再验证上传下载，不能把未启用存储说成可用 |
| P2 | 性能与容量 | 优先持续观察慢接口的P95和前端实际打开耗时；日报摘要按范围聚合。备份归档、磁盘容量、外部物流和模型连通性需单独运维实测，不以本机测试替代 |

## 验证范围和限制

- 完整回归覆盖库存与销售导入/撤销、备货审批/生产/运输/收货、财务/关账/核销/备份、达人内容、分销售后、岗位权限与并发保护。
- 日报重点验证：缺报与零、跨时区跨月、同口径比较、零基数、已撤销批次、广告费覆盖及疑似重复、汇率失效、实时重算和越权拒绝。
- 隔离HTTP和界面使用模拟数据，不向生产创建测试单据。
- 本轮不构成对实际仓库实物、银行到账或平台原始账单的审计；未核验真实GPT调用额度，也未对百世发运、付款、正式月结做写入操作。
- 测试数量、性能结果及本地界面验收记录见下方完成记录和 `work/diagnosis-20261123/`。
