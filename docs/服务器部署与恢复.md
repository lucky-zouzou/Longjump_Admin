# LOONG JUMP 修正版：服务器部署与恢复

本包包含业务源代码、公司账号登录服务、数据库迁移、完整备份恢复程序和自动测试。现有 Sites 版本继续使用 ChatGPT 登录；自有服务器版本使用公司邮箱及密码登录。两种运行方式使用相同业务代码。

## 1. 上线需要配置的内容

技术人员需准备 Linux 服务器、域名及 HTTPS 证书，并设置管理员邮箱和初始密码、数据目录与备份目录。这些属于部署配置，不需要另行开发业务模块。

运行环境：Node.js 24、pnpm 11.19.0。也可使用提供的 Dockerfile 和 compose.yaml。所有金额继续按 IDR 印尼盾整数存储；线下月份按印尼西部时间业务日期统计。

数据库采用服务器本地 SQLite，开启 WAL；适用于单实例内部业务系统。请勿将同一数据目录挂载给多个应用实例，或放在不支持 SQLite 锁的网络文件系统中。多实例扩容需要数据库架构调整。

## 2. 首次部署：Docker Compose

1. 解压文件，在项目根目录准备 `.env`：

```dotenv
LOONGJUMP_ORIGIN=https://你的域名
LOONGJUMP_ADMIN_EMAIL=管理员公司邮箱
LOONGJUMP_ADMIN_NAME=公司管理员
LOONGJUMP_ADMIN_ID=company-admin
```

2. 创建 `secrets/admin_password.txt`，其中只放管理员初始密码，至少 12 字符。密码不在代码中配置，不使用默认密码。容器进程为 UID 1000；确保该文件对 UID 1000 可读，并限制其他主机用户读取。首次账号创建后，该文件不会覆盖已有密码。
3. 执行：

```bash
docker compose build
docker compose up -d
docker compose logs --tail=100 app
```

4. 反向代理将外部 HTTPS 请求转给 `127.0.0.1:3000`，保留真实域名的 Host 和 Origin，不向公网开放应用的 3000 端口。参考 Nginx 配置：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_read_timeout 600s;
    client_max_body_size 22m;
}
```

此片段放在已经配置证书的 HTTPS server 块内。网页输入的文件每份限制 20 MB。

5. 打开域名，用管理员公司邮箱和初始密码登录。先建立员工账号、岗位、站点及渠道，再维护供应商、工厂、仓库、SKU 和期初库存。

账号仅由公司管理员或持有服务器管理权限的技术人员开通。系统没有公开注册入口。

## 3. 创建员工账号／重设密码

CLI 从标准输入读取密码，也支持通过 `LOONGJUMP_ACCOUNT_PASSWORD_FILE` 指向受保护的密码文件。不要把密码放在命令行参数中。

```bash
docker compose exec -T app node server/cli.mjs account:add \
  --id employee-sales-01 --email sales@example.com --name 印尼销售 \
  --role 销售 --site 印尼 < secrets/employee_password.txt
```

可用岗位：管理员、销售、运营、运营主管、新品开发、财务、供应链、工厂、海运。运营必须同时指定 `--site` 和 `--channel`；渠道为 TikTok 或 Shopee。销售首期站点必须为印尼。

对已有账号使用相同 `--id` 可重设密码，同时撤销该账号现有登录会话。命令中的姓名、岗位、站点和渠道会同步更新，应填写该员工实际资料。账号停用及岗位调整也可通过系统管理员的“账号权限”页面操作。

密码采用随机盐 scrypt 哈希；登录会话有效期 8 小时，Cookie 使用 HttpOnly、SameSite=Strict，并在 HTTPS 下设置 Secure。连续失败登录会临时限制尝试。

## 4. 不使用 Docker

```bash
pnpm install --frozen-lockfile
pnpm build:server
```

配置运行环境：

```dotenv
NODE_ENV=production
LOONGJUMP_ORIGIN=https://你的域名
LOONGJUMP_DATA_DIR=/srv/loongjump/data
LOONGJUMP_BACKUP_DIR=/srv/loongjump/backups
LOONGJUMP_BACKUP_RETENTION_DAYS=30
PORT=3000
HOST=127.0.0.1
```

先用 `node server/cli.mjs account:add ...` 创建账号，再用进程管理器启动 `node server/index.mjs`。通过进程管理器注入以上环境变量；Node 启动脚本不会自行读取任意 `.env` 文件。Docker Compose 会读取根目录 `.env`。

交付包内包含已构建的 `dist-node`；源代码变更时须重新运行 `pnpm build:server`。不要用普通 `pnpm start` 启动公司账号版本，该命令保留给原平台运行方式。

## 5. 从现有在线系统迁移

1. 管理员在修正版在线系统导出“全量备份”，得到 `.tar` 文件，包含 54 张业务表和全部已登记的发货照片／视频原文件。
2. 将备份放到服务器，使用**相同修正版源码**执行恢复：

```bash
node server/cli.mjs verify --input /安全目录/backup.tar
node server/cli.mjs restore --input /安全目录/backup.tar --target /srv/loongjump/restored
```

3. 查看新目录中的 `restore-result.json`，确认 integrity 为 ok、表数和文件数正确。恢复目标必须是新目录，程序拒绝覆盖已有数据。
4. 将 `LOONGJUMP_DATA_DIR` 指向恢复目录。为原系统用户绑定公司密码时，CLI 的 `--id` 必须沿用恢复数据库 `users.id`，才能保留订单归属和历史贡献。不要为同一员工随意创建新 ID。
5. 在恢复目录上完成登录、打开订单、查看凭证和财务导出验证，再切换正式访问地址。

从在线系统导出的备份不包含公司密码，因为在线版本使用 ChatGPT 登录。自有服务器导出的备份包含公司账号密码哈希；恢复后登录会话全部失效，需重新登录。

旧版只包含数据库 JSON 的备份不包含照片和视频原文件，不能作为完整迁移包。请从本次修正版导出完整 TAR。

## 6. 备份、校验和恢复

- 在线“全量备份”在导出期间短暂锁定业务写入，避免订单、库存和凭证引用错位。下载中断或失败后释放锁；异常断连由锁到期保护。未完整下载的文件不应使用。
- 自有服务器设置 `LOONGJUMP_BACKUP_DIR` 后，启动时生成当日备份，此后每天自动备份；默认保留 30 天。日志中输出成功或失败，不静默忽略失败。
- 自动备份先写 `.partial` 文件，校验内容长度与 SHA-256 后才改为正式 `.tar`。
- Docker 的 `company_backups` 是独立持久卷，但仍可能与数据位于同一服务器。技术人员应安排将备份复制到另一个存储位置；系统代码不内置任何第三方云盘密钥。

手工备份示例：

```bash
docker compose exec app node server/cli.mjs backup --output /backups/manual-backup.tar
docker compose exec app node server/cli.mjs verify --input /backups/manual-backup.tar
```

恢复时程序验证文件哈希、迁移版本、全部表及列、行数、外键、数据库完整性和凭证对应关系。使用当前源码已知的迁移创建新库，不执行备份中提供的任意 SQL。

建议技术人员每月恢复一次到新目录，核对订单数量、凭证和月度对账导出。恢复完成后才切换数据目录；保留切换前的数据目录作为回退点。

## 7. 更新与回退

升级前先完整备份；替换应用源代码／镜像后启动，系统按顺序自动执行尚未应用的数据库迁移。已经应用的迁移文件有哈希校验，不能手工修改。

本次新增迁移为 0007、0008、0009，保留原 0000—0006 不变。迁移只增加表、字段、索引及保护触发器，不覆盖已有业务记录。当前线上采购单、线下订单和退货暂无存量；已有选款阶段新品项目可继续使用。

回退不能只替换旧代码并继续写新数据库。应使用升级前匹配版本的完整备份恢复到新目录，再把旧代码指向该恢复目录。

## 8. 验证命令

```bash
pnpm test
```

此命令运行类型检查，分别构建自有服务器版和原平台版，再运行规则、权限、并发、财务、备份恢复及真实 HTTP 服务流程测试。测试全部使用临时数据库，不接触正式业务数据。

本包未替用户配置外部服务器、域名证书或企业账号名单。完成上述部署配置即可运行已实现功能，无需再补本次审查所列业务模块。
