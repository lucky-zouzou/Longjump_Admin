## 使用入口与角色

- 内部工作台：`/?page=distribution`，左侧独立“分销管理”，与“印尼线下批发”分列。包含商家店铺、入驻审核、分销订单、结算凭证，支持中文 / Bahasa Indonesia。
- 对外商家登录：`/distributor`，独立于员工登录；商家专属地址 `/distributor?store=toko-…`，仅对应账号可访问。
- 公开入驻：`/distributor/apply`。印尼语页面收集姓名、印尼 WhatsApp、城市、平台、店铺账号及收货地址；重复申请不会覆盖正在审核的资料。旧页面未带地址的申请仍作为不完整线索保留。
- 两个外部地址目前采用同域独立路径、独立身份认证，并未配置新的子域名。若以后使用专用域名，需要另行配置 DNS、HTTPS 和反向代理，不复制客户与库存数据库。

| 角色 | 本次范围 |
|---|---|
| 印尼运营 / 销售 | 录入本人商家或将已有客户纳入分销；查看本人商家、订单、归属回款及已分配申请；不能批准入驻或核销资金 |
| 管理员 | 全部分销汇总、分配申请负责人、准入审核、账号激活邀请 / 重置 / 停用；继续具有原订单管理权限 |
| 财务 | 全部商家与分销订单、付款凭证与实际银行流水核验、原订单财务处理；不能批准入驻或重置账号 |
| 商家 | 本店库存目录、图片和商品规格、自助订单、本人订单物流及支付状态、照片 / 视频售后、结算凭证上传 |
| 供应链 | 继续通过既有履约工作区处理分配给自己的分销订单出库，不获得商家账号管理权限 |

## 两条建店路径

1. **内部录入**：运营或管理员录入真实商家资料 → 原客户主档与待审核店铺在一个事务中创建 → 自动生成店铺编号、账号名和店铺链接 → 管理员核对资料后批准 → 生成 48 小时有效、一次使用的激活链接 → 商家自行设置密码。
2. **公开申请**：卖家填写申请 → 未匹配负责人时进入待分配池 → 管理员分配运营 / 销售 → 补齐、核对资料 → 管理员批准并关联已有客户或建档 → 自动生成店铺身份 → 在“商家店铺”生成激活邀请。

系统不生成可反复查看的明文密码。激活链接仅在创建时显示，由员工发给核实过的商家；没有集成自动发送短信、邮件或 WhatsApp。普通店铺链接不是登录凭据。

## 业务闭环与数据口径

商家下单 → 现有订单审批并预留库存 → 商家上传凭证 → 财务核实真实到账并关联原订单 → 供应链实际发货并扣库存 → 商家查询物流 → 退换货写入原售后总表（来源“线下分销”）→ 管理员审核、财务按原规则处理退款或同 SKU 换新。

- 商品只显示已进入印尼批发目录且有效发布报价的 SKU；继续使用 IDR。零库存商品可查看，不可下单；库存未知不当作零，也不参与可下单目录。
- 继续展示系统匹配的商品图片、材质、尺寸和装箱资料，并可下载产品图片。商家不获取采购成本、供应商资料、内部凭据或原图片存储地址。
- 对外界面和提示是印尼语。已有标准中文商品词使用受控词表翻译；未适配的中文商品字段显示资料待完善，不猜测材质或规格。人名、店名、SKU、商家自填及员工填写的业务说明保留原文；对客售后说明应由员工使用印尼语填写。
- 申请订单不扣库存，批准后预留，实际发货时扣减。沿用原 SKU、价格版本、库存锁、销售归属和履约账，不另建一套库存。
- 上传银行凭证只新增证据，不自动记为回款。核销须财务 / 管理员核对实际日期、金额、流水号；支持退回，原流水冲正后商家能看到状态变更；已关闭月份不能写入财务。
- 同一商家的重复订单请求、重复凭证请求、重复核销请求有幂等保护。最终财务继续受唯一银行流水和原账本约束。
- 管理端商家汇总为累计订单、累计净发货（出库减退货）、归属订单净回款（含退款、冲正及撤销分配），不混入普通线下订单或未分配银行预收款。结算凭证列表显示最近 200 条；完整历史保留在原订单账本。
- 历史线下订单不会被自动当成分销订单。历史已启用分销链接的客户迁移为已有商家身份；旧专属链接保持兼容，激活账号后失效。新商家不能通过旧接口绕过准入审核。

## 账号与恢复边界

新增迁移 `0053_distributor_stores.sql`：店铺、独立会话、登录限速、付款凭证表。会话 cookie 为 HttpOnly、SameSite=Strict，HTTPS 下启用 Secure；外部账号不能访问内部 API，内部登录 cookie 不能充当商家身份。

生产 Node 24 使用 Web Crypto PBKDF2-SHA256 600,000 次加盐计算密码散列；激活与会话 token 只存摘要。账号限速，登录会话 8 小时，邀请 48 小时；停用或重置立即撤销旧会话及旧密码。管理端数据接口不返回密码摘要、salt 或会话令牌。

该迭代数按 [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) 选择。Node 生产路径已通过真实 HTTP 测试；Worker 构建通过不代表其托管平台登录运行时已验收，[Cloudflare Web Crypto](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/) 的运行时上限需单独验证。不支持该计算强度时返回服务不可用，不降低密码保护。

全量备份包括店铺、密码摘要、订单与凭据，受原管理员权限和备份保护；不导出会话 / 登录尝试记录，并清除备份中的待激活链接。恢复后商家重新登录，未激活账号重新邀请；不会恢复旧浏览器会话或重复激活令牌。新业务表受维护锁保护。
