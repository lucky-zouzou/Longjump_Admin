# 系统修复与图形销售看板

本次包括审查中 F01—F09 的修复、备货计划批量导入与删行整合、Excel 组件升级，以及销售看板图形化。

## 运营使用变化

- 销售文件默认作为“部分 / 增量销售”。该日首次上传完整日报时，可以选择“完整销售日报”。已有销量时不允许再叠加整份日报，以免重复扣库存；应先核对、冲销错误批次或继续上传不重复的增量。
- 分批上传完成后，填写核对依据、勾选确认，再点击“确认该日销售完整”。没有销量的日期也用这个入口确认零销售。
- 后续新增或冲销销量，日报自动恢复为待核对。只补录广告费用不会改变销售完整度，也不扣库存。
- 旧历史批次无法证明覆盖全天，因此保持“部分”状态；已有销量保留，按实际观察日参与预测，未知日期不补零。需要完整覆盖的历史日报可在近90天窗口内重新核对确认。
- 月度备货支持模板导入、合并或替换草稿、删除单个 SKU 与撤销删除。删除需求不删除库存、SKU 主数据或已批准订单；提交后重新打开使用已保存的清单。

## 图形看板

- 销售趋势可切换“净销售数量”与“销售额 / 投放成本”。后者始终使用选中币种和相同金额坐标轴。
- 渠道销量、前10热销SKU和前10投产比使用横向条形图，保留真实数量和倍数。点击热销SKU可打开对应明细。
- 完整排名、每日明细和渠道金额可展开查询并导出。无记录日期断线；费用补录不能制造零销量点；明确确认的零销售日才按零显示。
- 金额或费用不完整的日期不绘制相应金额点；缺费用、零投放和缺销售额仍保持不同状态，不显示虚假的无限投产比。
- 刷新保留当前报表；切换筛选则等待新范围数据。同步失败显示过期提示和重试入口。
- ROAS 仍为销售额 / 广告成本，不是利润率。贡献利润榜与自动广告预算调整不在本次范围内，因为需要补齐成本与归因数据。

## 补货与权限

- 财务及其他业务记录不再带回未筛选的原始 JSON；计划变更改用已解析字段。
- 未完成审批、盘点、运输等记录不受已完成历史条数挤压。生产单和相关明细保留完整供给计算基础。
- 已完工订单采用实际产量，包括零；取消、质检拒绝不作为正常生产供应。完工提交增加事务内状态校验，拒绝并发覆盖。
- 线下实发和退货按实际扣减的库存渠道进入需求历史，合计只计一次。线上与线下分别使用各自有效观察日计算日均，避免缺失线上日期变成零。
- 逐日库存只在每批自己的预计到货日期加入该批数量。未知和已逾期到货不当作今日已收货；显示最早缺口日期和预测周期内最大缺口。仍需供应链维护准确 ETA，未确定日期的生产不能保证中途不断货。

## 发布说明

新增迁移 `0011_young_wild_child.sql`，只给 `sales_imports` 增加 `report_kind`，不删除或重写历史销售及库存。

部署流程增加自动测试、同一分支发布串行控制和升级前完整备份；健康检查使用精确容器状态，并请求 `/healthz` 验证数据库及目标版本。SSH 密钥或备份失败会阻止重启。首次安装环境仍需先按部署说明初始化账号、数据目录和备份目录；此流程用于现有服务更新。

应用与数据库恢复属于不同操作。此次迁移为追加字段，但任何恢复操作仍应使用已经验证的备份和匹配版本，不能覆盖运行中的数据库。

Excel 使用 SheetJS 官方分发的 0.20.3，锁文件固定下载完整性；保留 Excel/CSV 模板及读写往返测试。
