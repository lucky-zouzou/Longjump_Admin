# 2026-09-30库存期初切换

Node正式部署提供管理员专用 `/admin/inventory-baseline`，普通岗位不可访问。源码不包含真实库存文件或历史业务数据。

操作顺序：上传已核对的五站JSON → 查看各站及渠道预览 → 确认范围 → 服务器完整备份并校验 → 单一数据库事务清理和导入 → 核验数量。

同站点所有仓库按SKU汇总，TikTok与Shopee均分；奇数余件依次交替分配，站点内和全局渠道差额最多1件。仅计可用量，退货在途不计可售；SKU按系统既有规则去首尾空格并转大写。保留原文件哈希和每行来源。

清理线上销售导入、记录、广告费、需求修正，以及印尼线下订单、分配、出库、退货、结算、银行收款和月度关账记录。旧待审核盘点拒绝并注明期初切换。保留客户、用户、拜访、合同、售后、采购生产、历史审批、SKU供应配置和审计记录。旧库存流水保留，新增期初调整流水使余额衔接；不删除凭证物理文件。

存在2026-10-01后的交易、运输待上架或隔离库存、非五站库存时先阻止处理。预览到执行期间业务有变化则重做预览。清零与导入失败整体回滚，不产生半完成状态。

完整备份及切换快照在 `LOONGJUMP_BACKUP_DIR/inventory-baselines/` 下，文件权限600。不会被普通30天日备份清理任务移除。

切换后没有任何业务变化时，可在同页撤销，恢复受影响表并追加恢复流水。已有新业务后拒绝直接撤销，使用完整备份在隔离目录核对恢复，避免覆盖新业务。原附件保留以供恢复，普通业务界面不再显示已清理订单附件。

数据库日期保护以审计中的最近一次有效切换为准，禁止将2026-09-30及之前的销售、广告费、线下交易再次计入新期初。撤销切换后解除此日期保护。正式销售从2026-10-01起录入，导入时按正常业务流程扣减。
