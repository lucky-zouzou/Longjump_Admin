# 库存与销售导入

各录入页面均提供 Excel（`.xlsx` / `.xls`）和 CSV 导入。上传后先预览，确认前不会写入数据；可以选择工作表。CSV 支持 UTF-8 和常见中文 GB18030 编码。文件最大10MB。

## 页面与生效方式

| 页面 | 可导入内容 | 确认后的效果 |
| --- | --- | --- |
| 库存流水 | 站点、渠道、SKU、商品名称、盘点实数、调整原因 | 管理员整批设置可售库存；运营整批提交盘点差异，复核通过后生效 |
| 历史到仓 | 多张到仓单，每行明确SKU及站点渠道分配 | 整批入库并记库存流水；关联生产批次的货品进入待上架 |
| 销售数据 | SKU、销量、可选商品名称 | 当前运营站点渠道整批记录销售并扣库，保留原文件和平台批次防重规则 |
| 海运批次 → 目的地到仓登记 | 本目的地各SKU实收及隔离数量 | 导入到到仓表单，补齐到仓单号、凭证，确认后合格品进入待上架，异常品进入隔离 |
| 海运批次 → 历史单系列到仓 | 本批次SKU实收数量 | 导入到实收表单，补齐单号、凭证再确认；此历史流程隔离数量只能填0 |
| 印尼线下批发 → 新增出库申请 | SKU、件数、成交单价IDR | 替换当前订单商品明细，核对客户、日期和账期后提交审批 |
| 印尼线下批发 → 实际发货登记 | 本订单各SKU实际发货数量 | 替换本次发货数量，文件未包含的SKU本次不发货；核对物流与实际交付后提交 |
| 印尼线下批发 → 退货验收入库 | 单个SKU的数量、收回日期、凭证和原因 | 填入验收表单，确认仓库实收、质检结果后提交；每份文件一条明细 |

## 使用步骤

1. 到对应页面下载模板。订单和批次模板会列出当前单据的SKU及明细编号。
2. 保留表头，只留下本次需要处理的行，删除其他明细行。SKU和各类单号使用文本格式，防止前导零丢失。
3. 填写实际数量，不要填写公式。若原表使用公式，先复制并“粘贴为数值”。数量只能为整数，不会自动四舍五入。
4. 选择文件，检查工作表和预览。文件存在错误时，显示原文件行号并阻止整份导入；可以下载全部错误明细后集中修正。
5. 确认导入。库存盘点和历史到仓直接整批保存；订单、发货、运输到仓和退货先填入表单，再通过原业务确认按钮提交。

## 库存盘点

- 每次最多200行。同一站点＋渠道＋SKU不能重复。
- “盘点实数”是目标可售库存总数，**不是本次增加数量**。填0表示清零，空白不等于0。
- 每行调整原因至少4个字符。与现有数量一致的行记为无需调整，其余行整批处理。
- 运营只能提交本人站点渠道的盘点，不会绕过供应链复核。
- 可售库存的修正保留预留、待上架、隔离的原业务口径，不能拿在途或隔离货冲抵可售库存。
- 导入成功后，同样的文件内容即使改文件名或调整行序也不能再次覆盖库存；新一次盘点请填写新的核实原因（建议包含盘点日期或单号）。

## 历史到仓

- 每次最多200行。**一个到仓单号对应一个SKU**。同SKU分配给多个渠道时，使用相同单号，SKU、名称、生产批次及凭证须一致。
- 一张仓库单有多个SKU时，在单号后加明细后缀，例如 `WH-202609-001-01`、`WH-202609-001-02`；凭证可以引用同一张仓库原单。
- 供应链必须填写系统已有的历史生产批次ID，且该批次须处于等待到仓状态，SKU、总数及渠道分配须匹配。管理员可不关联批次，处理经过核实的期初或例外入库。
- 同一生产批次不能在文件里拆成不同到仓单重复入库；已使用过的到仓单号会被拒绝。
- 任一行错误、重复单号或并发冲突，整份文件都不会写入，不会出现一半成功一半失败。大量渠道分配超出单次事务容量时，页面会要求拆分文件。

## 销售与批发

- 平台销售最多5000行，需要先选择销售日期和填写唯一平台报表／订单批次号。支持模板表头和常用 `Seller SKU`、`Units confirmed`、`Quantity` 等表头。同SKU销量会按原规则汇总。
- 平台销售仍由对应运营导入，管理员及供应链保留原监控权限；销售日期仍限定近90天。
- 印尼线下销售只能由批发订单实际发货产生，不得再作为平台销售导入，以免重复扣库。
- 批发订单每次最多20个SKU。商品须已建档，价格以整数IDR填写。导入不会跳过审批、锁库、财务或实际交付核实。
- 运输或订单存在同SKU多条明细时，保留模板中的“明细编号”，防止数量对应错误。文件中的SKU或明细编号必须属于当前单据，数量不能超过剩余可处理数量。

## 部署

沿用现有数据库结构，无新增迁移。拉取代码后重新构建并重启当前部署，原库存、销售和单据数据保持可用。
