# 商品成本与动销分类

入口：成本利润透明 → 商品成本与动销。与“批次成本与结算证据”共用工作区，商品参考成本和实际批次核算独立保存。

## 成本导入与权限

- 管理员、财务可上传原始 `.xlsx`、核对预览、确认有效行和修订历史；两步操作前后校验内容及版本。重复换文件名不产生重复成本版本。
- 默认 Sheet2 为准，Sheet1 只补缺失项。补入旧分项后如果与主表综合成本不符，撤回该次分项补缺、保留主表并提示；两张表均无值的字段保持未知。没有表头的 Sheet3 不自动合并。
- 按系统已有 SKU 精确匹配（忽略首尾空格和大小写），不猜测相似 SKU、不创建商品。未知或歧义 SKU、重复行和加总错误单独列出；必须修正或明确确认跳过才可提交其他有效行。
- 币种为人民币／件，存储保留四位小数以容纳海运分摊。采购、海运和综合成本均可留空；缺失不按 0 补齐。综合成本与已知采购＋海运差异超过约一分钱时要求核对。
- 费用范围默认“待核实”，也可核对为“采购＋海运”或“完整到仓”。税费、入仓费用没有确认时不能把该成本视为完整利润依据，也不会自动成为已核定批发报价。
- 运营只看本账号站点／平台已有库存或销售的 SKU 成本；运营主管、财务、管理员查看全局。工厂、线下销售及供应链不能通过此接口获取商品成本。批次核算账册的独立授权保持原样。
- 每次修订保存新版本、生效日、原文件摘要、工作表／行号、分项来源、操作人及理由。未来生效版本单列，不提前覆盖当前成本。导入不改销售、库存或历史订单。
- 单次最多 900 条有效站点成本原子提交；超过则要求拆分。所有新表纳入全量备份、恢复和维护锁保护。

## 建议初始分类

按“站点 × 平台 × SKU”独立计算，截止各站点昨天，使用过去 28 个完整自然日。前提：28 天完整日报、上架至少 28 天、库存及预留正常；缺报、半天日报及可疑重叠报表不计作完整日。

| 分类 | 初始条件 |
| --- | --- |
| 爆款 | 28 天日均销量 ≥ 10 件，且 7 天日均 ≥ 7 件 |
| 热卖款 | 未达到爆款，28 天日均销量 ≥ 3 件 |
| 平销款 | 数据充分，未满足其他三类条件 |
| 滞销款 | 可售库存 > 0，连续有货且连续 7 天零销售；或 28 天日均 < 0.5 件、库存覆盖 ≥ 90 天，且最近 7 天连续有货经过核实 |

滞销条件优先于历史热卖量级，避免历史大卖掩盖最近停止动销。连续有货证据沿用零销量模块的核实区间及库存日快照；快照发现缺货时暂停零销量滞销判断。

数据不足、新品或零销量期间缺货时显示“待核实／观察”及具体原因，不强行纳入四类。近 7 天相对前 7 天的增减趋势另列，销量等级不代表利润等级，不自动改价或下采购单。

阈值仅管理员可调整，保存新规则版本及依据；建议积累完整数据后按实际站点规模复核阈值。

## 页面与金额含义

- 四类卡片可点选筛选，支持站点、平台、SKU／名称检索及分页。
- 明细列出 28 天／7 天销量、日均、趋势、可售量、库存覆盖、匹配成本、缺报日期和核实原因。
- 库存金额 = 当前可售数量 × 当前有效单位参考成本；统计覆盖范围显式展示。它是经营参考金额，不能替代按批次、税务及财务政策形成的存货估值。
- 缺少成本或库存异常时金额显示待核实；未知分项不挤入零成本汇总。
- 真实成本源文件与待导入数据仅在本地保留，不进入公开 Git 仓库。上线和正式数据写入需要用户对完成版本确认。

## 验证范围

覆盖主辅表规则、四位精度、异常跳过确认、不可变修订、重复文件、过期预览、未来生效、角色／站点隔离、实际 HTTP 接口、分类边界、缺报／重叠报表、站点时区以及完整备份恢复。桌面和移动布局使用同一响应式页面。
