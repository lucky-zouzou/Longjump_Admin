# 多 SKU 到仓入库

## 操作流程

1. 在「历史到仓」填写到仓单号、实际到仓日期、站点、签收凭证编号和入库说明。
2. 手工增加商品行、导入 Excel/CSV，或粘贴带表头的表格。一个单号可以包含多个 SKU；同一 SKU 分配到不同渠道时各填一行，数量合计为实收，不重复计算同批实物。
3. 点击「校验并预览库存变动」，查看每行的目的仓、渠道、实收及可售/待上架/隔离库存变化。
4. 核对新增数量未计入期初库存或其他入库单，确认可售商品已验收合格，再点击「确认整批入库」。成功后保存单据、库存流水、操作记录及逐行回执。

每次最多 200 行。同一单号的站点、日期、凭证、说明须一致；不同站点使用不同单号。商品必须已存在于 SKU 主数据，错误行必须修正后才能整批提交。实际到仓日期与系统登记时间分别保存。

## 库存与权限

- 管理员可以登记无关联批次的例外入库：已验收合格增加可售，未验收或破损进入隔离。隔离货物沿用「库存流水」的放行/报损流程。
- 供应链须关联旧版「等待到仓」生产批次；SKU、总数和渠道分配须与批次完全一致，入库后进入待上架，由运营确认上架。旧批次跨站点时，各站点分单并在同一份文件中一并导入，整批校验后推进旧批次状态。
- 已建立海运主批次及目的地分腿的货物继续使用海运到仓/上架流程，避免重复入库。
- 沿用站点＋渠道＋SKU 库存账。目的仓为主数据中的启用仓，每行保留仓库编号与名称；这不引入同一渠道多个物理仓的独立库存账。
- 运营仅查看本人站点渠道的单据明细及相应合计。其他角色沿用库存模块读权限，写权限不扩展。

## 一致性与发布

- 预览只读。确认时重新核对库存、SKU、仓库及关联批次；任何变化均要求重新预览。
- 单号跨新版/旧版去重，数据库唯一约束和事务内校验防止并发重复提交。
- 同一事务写入整批单据、明细、库存及流水；任一错误整批回滚，不覆盖已有库存。
- 新增 `0017_inbound_documents.sql`，保留旧版到仓表与记录。新表具备维护锁保护，并纳入动态备份表清单与备份版本。
- 先按现有发布流程备份，再应用迁移与代码。此次迁移不修改现有库存。

## 验证

覆盖一单多 SKU/多渠道、Excel/CSV/粘贴、错误行、未知 SKU、错误目的仓、重复及并发提交、库存变化冲突、旧版批次兼容、隔离放行/报损、200 行入库、角色读取范围和维护锁。浏览器使用本地虚构数据核对桌面及手机回执，未向正式库存写入测试数据。
