# 全站与财务归集诊断 · 2026-11-26

## 结论与检查范围

系统已经具备业务协同、单据追踪、部分财务核算及月结的基础，但还不能把各个页面上的金额直接相加，视作公司全部收入、支出或净利润。下一轮应优先补齐财务流程的断点，再统一分类、查询和管理层结果页。

建议的方向是：**岗位录入业务事实，财务集中复核；各子账保留明细，统一财务工作台按业务线、资金性质和核算维度汇总。** 财务不再把业务人员录过的数据重新录一遍。

- 检查基线：本地 `codex/ui-refresh-20261126`，提交 `88076e2`。该工作树包含岗位入口、分销交接和全站 UI 的本地改动；不能据此宣称正式站已具备这些本地改动。
- 本轮检查：业务代码、数据库约束、财务岗位本地界面、全量自动回归、9 组补充诊断场景。
- 所有写入测试均使用内存或临时合成数据库，标记 TEST。没有修改正式单据、财务数据、人员配置或生产部署。
- 未抽取正式银行流水、真实发票与真实账套逐笔核对。因此下文是系统设计与运行逻辑诊断，不代表正式账面金额已全部核实。

| 印尼线下分销 | 现金/账期/寄售，财务确认放货，银行收款可分配多张订单，退货与冲正 | 中央月结完整保留未分配预收与银行事件，不只保留订单核销结果 |

| 普通费用 | 申请、主管审核、关联应付、分笔付款、另一财务银行核对 | 服务/办公/物流等独立应付来源、错账更正、跨月继续支付 |
| 考勤与请假 | 个人与审批入口、飞书同步代码及映射设计 | 当前正式飞书数据同步需单独实测确认；签发人事月度汇总后再接财务，不能把缺卡直接当扣薪 |
| 小品同学 | 手册、每日销售、贡献利润、生产建议、备货履约等只读查询 | 应收逾期、实际回款、实际支出、付款排期和分类费用的专用查询工具 |

已验证的基础控制应保留：审批不等于付款；客户截图不等于实际到账；缺失金额不补零；核销不新增现金；寄售出库不当已售；样品不计销售收入；原币与人民币分别保留；关闭期间有版本快照与写入约束。

## 优先处理的问题

### 1. 上期费用关账后，本期付款被阻断（P1，已复现）

合成案例：9 月已批办公费用 100 元，9 月关账，10 月 11 日登记实际付款。系统返回“该期间已关账”，付款没有写入。

原因：工作台在付款前同时检查原申请业务日、原结算日和原应付日期是否开放。这使正常的跨月清偿也必须先反关账，与应付余额结转需求不符。

建议：保持上月原费用、原应付和月结快照不变；允许本月生成付款与核销事件，关联上月未付余额。改原单和支付旧余额应走不同规则。反关账只用于确需修订历史事实的情况。

代码定位：`lib/finance-workbench.mjs:58`、`:99`。证据：`F02-payment-after-prior-month-close`。

### 2. 中央月结没有完整覆盖未分配客户预收款（P1，已复现）

合成案例：印尼客户银行到账 500,000 IDR，尚未分配销售订单。线下台账能显示该现金；中央月结的订单回款为 0，未保存这张银行收款记录，也没有因这笔外币预收提出汇率缺口。

这里不是原始数据丢失，也不是应该把“核销回款”改成“银行到账”。两者必须分别保存。目前中央快照只是没有覆盖完整资金子账。

建议：中央快照增加按截点还原的银行收款、退款、冲正、已分配与未分配余额，以及法人、银行账户、币种、汇率依据。银行到账只统计一次；分配到多个订单只影响核销关系。全部子账与中央月结共用期间状态展示。

代码定位：`lib/finance-ledger.mjs:146`、`:153`、`:165`，`lib/wholesale-export.mjs:19`。证据：`F04-unallocated-offline-bank-receipt-in-central-snapshot`。

反向检查：关闭中央期间后补录该期间的线下银行收款确实被数据库约束拦截，未发现可以绕过该锁的情况（F05）。

### 3. 非商品采购费用只能申请，缺少完整结算来源（P1，已复现的能力缺口）

当前普通费用财务复核必须选择已核对的 `supplier_bill`，而该账单必须有批准的采购订单、SKU、数量、采购价和收货匹配。办公、软件订阅、单独仓租等不能合理地套用商品采购单。

现有一期文档已明确这项限制，不应把“有申请入口”理解为“各类费用都已闭环”。补充测试成功提交办公申请并完成主管审批，但建立不关联采购单的服务账单时被拒绝。

建议新增经过审核的服务/费用应付类型：办公、仓储、运输、软件订阅等按合同、服务期、账单及验收依据核对；商品采购继续做采购—收货—票据匹配。统一进入原应付、付款、核销体系，不另造第二套现金账。

代码定位：`lib/finance-workbench.mjs:78`、`lib/finance-ledger.mjs:126`。证据：F01。

### 4. 已批申请与错误付款缺少正常更正入口（P1，已核对）

已批准申请不能撤回；工作台付款禁止从旧资金账直接作废或改写；工作台自身又没有付款冲正、更正重开动作。防止旁路修改是正确的，但仍需有受控的纠错流程。

建议：更正申请 → 独立复核 → 撤销错误核销关系或登记反向事件 → 恢复可付余额 → 新凭据重新登记。保留原单、原因、经办人与复核人。已关账部分采用当前期间更正规则，不能靠删记录修账。

代码定位：`lib/finance-workbench.mjs:60`、`:90`，`lib/finance-ledger.mjs:98`。证据：F07。此建议针对工作台付款；印尼线下回款已有冲正，不能笼统说全站都没有更正。

### 5. 历史月份、跨月待办和付款日期需更清楚地区分（P2，已复现）

9 月费用、10 月实付 100 元，在当前“费用与付款”页选择 8、9、10 月，未办结申请都可能进入列表，其汇总均显示 100 元实付。页面确实写明“包含所选月历史及所有未办结申请”，所以这不是单笔现金被写入三次；但不能把这些汇总当作三个月各自的现金支出。

建议分开显示：

- 本月发生的费用，按业务归属日；
- 本月实际收付款，按银行日；
- 截至本日未办结事项，跨月展示；
- 截至月末应收、应付、预收、预付余额，按期末截点。

代码定位：`lib/finance-workbench.mjs:118`，`app/people-workplace.tsx`。证据：F03。

### 6. 财务组织授权与原资金账权限不是同一边界（P2；启用分国财务前必须处理）

撤销某财务的组织授权后，工作台不再返回该组织可选应付；但此人保留“财务”角色时，仍能读取旧中央资金账。现有文档把旧入口定义为总部财务全局权限，这是已知设计，不是本轮发现的生产越权事件。

建议明确设置“总部财务”与“范围财务”，将列表、汇总、导出、凭据下载、AI 查询共用同一权限判定。若团队只有总部财务，可维持全局授权；不能在增加国家财务时只收窄新工作台。

代码定位：`lib/finance-ledger.mjs:24`、`lib/finance-workbench.mjs:118`。证据：F06。

### 7. 财务费用页会随单据增加产生大量查询（P2，已量测）

| 合成申请数量 | 返回明细数量 | 一次读取的 SQL 执行数 | JSON 大小 |
|---:|---:|---:|---:|
| 1 | 1 | 27 | 5,828 字节 |
| 100 | 100 | 225 | 154,809 字节 |
| 300 | 300 | 625 | 456,209 字节 |

每行分别读取付款链接与附件，且列表、历史事件没有服务端分页。上述不是生产网络耗时，但查询增长已明确。

建议：权限范围在 SQL 层过滤；付款、附件、事件按当前页批量读取；待办计数与金额汇总独立聚合；明细服务端分页，附件按需展开。对账、付款写入仍实时核验，不为了快而缓存过期余额。

代码定位：`lib/finance-workbench.mjs:120–136`。证据：F09。

### 8. 小品的财务提问仍缺专用读数工具（P2，已实测）

| 测试问题 | 当前返回 |
|---|---|
| 本月线下回款有多少？ | 引导查看线下回款，没有金额 |
| 这月回款有多少？ | 引导资金账或线下账，没有金额 |
| 公司这月实际支出了多少钱？ | 未命中业务工具，回退岗位手册 |

不是换一个更大的模型就能自动修复。当前工具列表明确不让模型猜测回款，缺的是授权范围内的财务事实查询。

建议新增：实际收付款、应收逾期、应付到期、分类费用、广告预算执行、月结缺口六类只读工具。回答采用“结论 → 范围和截止时间 → 已核/待核金额 → 原单依据 → 下一步负责人”。对缺失分类、缺汇率、未对账项目说明缺口，不给完整净利润结论。

代码定位：`lib/employee-ledgers.mjs:24`、`lib/employee-business-router.mjs:8`。证据：F08。

## 财务分类建议

采用“一个财务工作台、多个业务子账、统一维度”，避免把各岗位菜单复制成一张混合大表。

| 财务工作台入口 | 汇集内容 | 要分开的金额 |
|---|---|---|
| 今日待办 | 待复核、待付款、待银行核对、到期催收、缺凭据、月结差异 | 待办数量与金额分别展示，说明统计范围 |
| 应收与回款 | 平台结算、国内分销、印尼现金/账期/寄售 | 合同待收、已确认应收、实际到账、订单核销、未分配预收、退款 |
| 应付与付款 | 工厂货款、运输、仓储、办公、订阅等 | 应付、申请占用、预付、实际支付、已核销、待核对 |
| 营销投入 | 广告、达人佣金/奖励、样品、寄样运费、内容制作 | 预算、充值、实际消耗、可用余额；实物样品成本与现金运费 |
| 资金与对账 | 各法人银行/现金账户及平台钱包 | 实际现金、内部划转、提现在途、手续费、未匹配流水；划转不制造收入费用 |
| 月结与经营分析 | 各子账勾稽、汇率、库存价值、费用归属、关账快照 | 已核贡献利润、额外经营费用、待核部分；全量覆盖前不标“公司净利润” |

工资、税费、固定资产等以后需要纳入时，设置独立受限子账或接入现有专业财务系统；当前系统尚未覆盖，不在此次诊断中自动新增规则。

每笔财务明细建议具备以下维度，能从源单带出就不要让财务重填：

| 维度 | 示例与作用 |
|---|---|
| 公司/法人、银行账户 | 识别钱属于谁，禁止无依据跨法人核销 |
| 业务线 | 线上零售、国内分销、印尼分销、营销寄样 |
| 金额性质/费用科目 | 收入、应收、应付、预收预付、采购成本、运费、广告消耗、办公等 |
| 站点、平台、店铺/广告账户 | 印尼 / TikTok / 某店铺；广告充值与消耗需同账户可追踪 |
| 部门/成本中心、负责人 | 印尼 TikTok 运营、供应链、总部；经办人不自动等于费用承担部门 |
| 来源单据/项目/批次 | 销售单、采购单、运输票次、合作轮次；唯一来源加事件版本，防重复记账 |
| 日期 | 业务归属日、应付到期日、实际银行日、记账期间分开 |
| 币种与折算依据 | 原币金额、核定汇率及版本、人民币金额，参考行情单列 |
| 状态与证据 | 待核/已核、待收付/部分/完成、冲正、凭证、复核人与审计 |

分类示例：一笔印尼 TikTok 达人寄样快递费，其业务线是“营销寄样”、费用性质是“样品运费”、承担成本中心是“印尼 TikTok 运营”、经办部门可能是物流。按国家、费用类型或部门查看时，都是同一笔金额，不分别记三遍。

多业务共用费用需记录分摊规则、覆盖期、基数、分摊前后合计和财务确认。采购付款不能全部自动当当期费用；库存成本转出、样品领用与实际销售成本必须关联原批次，防止重复扣减。

维度设计参考了 [ERPNext 官方 Accounting Dimensions 文档](https://docs.frappe.io/erpnext/accounting-dimensions)：经济性质与部门/项目等分析维度分开，支持明细行归属；历史记录不会因为新增维度自动补齐。对应本系统，旧数据应保留“待归类”，明确起算日和人工核验，不猜测历史部门或法人。

| 导航与表格 | 本地已有全站统一样式 | 财务按六类工作组织入口；统一月份/截至日期/币种口径，金额和异常可点击追溯。低风险项折叠，待处理项优先 |

## 建议实施顺序及完成标准

### 第一轮：先解决能否完整走通

1. 开放本期支付上期未清应付，历史快照不变。
2. 补齐非采购费用来源与完整审核链。
3. 提供已批准申请/付款的受控更正流程。
4. 中央月结完整纳入银行预收、退款及冲正事件，显示各子账关账状态。

验收必须覆盖：部分付款、跨月付款、付款冲正后重录、一笔银行款分配多单、未分配预收、同币种不同法人、月底前后反向事件、重复提交及并发。禁止为通过流程直接删历史记录或伪造采购单。

### 第二轮：统一财务分类与界面

1. 建立统一维度字典、来源事件标识和可追溯汇总层。
2. 重组上述六类财务入口；按资金性质分别汇总。

### 第三轮：让小品给管理层可用的答案

- “下周需要付哪些钱？哪些可以等？”
- “印尼广告花了多少，预算还剩多少？”
- “国内分销哪几个客户逾期，谁在跟？”

每条回答都要求：金额口径、时间、法人/站点范围、数据完整性、可点击原单、下一责任岗位。审批、付款、核销仍由授权人员执行，小品负责查询、解释与拟建议。
