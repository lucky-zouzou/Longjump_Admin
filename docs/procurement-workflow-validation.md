# 备货成本、采购与发货审核闭环验收

日期：2026-11-04。本轮代码仅在本地，未上传、合并或发布。保留此前运营移交模板修复提交 `4ffd1e2`。

## 已实现流程

1. 运营在补货驾驶舱填写需求，按本站点、SKU和生效日期自动匹配人民币成本，显示单位成本、合计、版本和缺失提示。服务端提交时重新匹配并保存快照，不接受客户端伪造成本。
2. 供应链按工厂和系列汇总采购。已有采购成本明细可带入参考价，只有到仓总成本的商品仍需核定采购价。数量来自运营需求，币种、税率、交期、付款及赔偿条款逐单确认。
3. 管理员批准月度备货后，系统冻结采购单并生成对应工厂的生产订单。工厂导出核对、接单回复交期，再更新生产、完工及质检进度。
4. 交期临近提示供应链。质检通过后，供应链读取当前可售、在途和与补货驾驶舱相同的完整日报需求预测，提交发货数量、目的仓及需求依据。
5. 采购总量不变时允许改配站点：逐项填写调出站点、平台和数量，管理员确认后才更新生产单发货分配。原采购需求不覆盖，保留调整前后记录。待审也预占调出份额，不能挤占既有通知或已发数量。
6. 发货通知批准后才对工厂开放。工厂实际发货、上传签字附件并提交装箱清单；供应链复核后按实发数量创建海运，继续既有开船、到仓、上架流程。

“自动下发”指进入对应工厂的系统账号与待办，不代表向工厂自动发送邮件或即时消息。海运单创建不会提前增加海外可售库存。

## 守卫与兼容

- 只有到仓总成本时不代填工厂采购价；缺成本不按零元计算。成本版本变化后，旧采购草稿须重新核对。
- 工厂可看已批准采购价，内部到仓成本参考、销售单价和广告成本仍隔离。
- 新发货通知需要独立管理员审批，自己提交的通知不能自批。待审通知不能上传装箱、登记发货或转海运。
- 重复审批、并发审批与取消、重复海运转单均有版本与数据库守卫。
- 驳回或未发取消释放预占；已批准通知取消不会自动反向修改其已批准站点分配，后续再调整仍须送审。
- 已批准发货分配与原采购分配分开保存。剩余生产按各站实际未发量计算，避免分批发货后把剩余数量按原比例重新摊分。
- 新迁移 `0040_dispatch_approval.sql` 保留历史通知的已批准状态；正式库尚未应用。
