# 零销量预警与优惠申请

入口：侧栏“零销量与优惠”，默认展示五站总览。覆盖马来西亚、印尼、泰国、越南、菲律宾的 TikTok / Shopee。管理员、财务、供应链和运营主管查看全盘；运营仅查看、核验本站渠道。主管只读统计，不获得优惠申请、金额和附件权限。工厂继续隔离。

优惠申请仍为印尼试点，金额为 IDR；其他站点可核验在售并记录改进措施。财务独立核算，管理员独立批准；供应链只读库存和处理状态，不能获取销售价、广告成本或凭证。

## 五站管理看板

- 首屏展示近7天日报零销量条数、去重 SKU、对应可售件数、连续在售预警和缺报数量。“条”按站点＋渠道＋SKU统计，同款跨站点渠道分别计数；全局去重商品数单独显示。
- 日报零销量要求当前有可售库存、7天日报完整且无正数销量。缺少连续在售证据的单独标记待核实；连续在售有货满7天才正式预警。
- 缺报不算零，没有完整资料可判断时显示“—”。零销量占比的分母仅为当前有库存且7天日报完整的记录，部分报齐只代表已核实部分。
- 五站卡片和渠道矩阵展示数量、库存、统计期间、负责运营、日报覆盖和缺报日期，点击可下钻。明细支持站点、渠道、状态、关键词及库存／零销量天数排序。
- 库存 Top 10 仅列日报完整的零销量商品；连续在售预警分为7–13天、14–29天、30天及以上三个互斥组。手机使用卡片布局，每15秒刷新。
- 迁移 0023 将观察触发器扩展到五站，按当地日期记录，保留既有证据和申请，不回填历史、不改变库存。

## 预警口径

- 按站点当地时间，截止昨天的7个完整自然日：马来西亚、菲律宾 UTC+8；印尼按 WIB、泰国、越南 UTC+7。每日必须有未冲销的完整日报或明确零销售确认；部分销售、仅费用补录、缺报都不能当成完整零销量。
- 正数销量不被退货／退款抵销。当前可售为 inventory_balances.qty - reserved_qty；待上架和隔离本来就不在 qty 中，不重复扣除。
- 连续在售且有货达到7天才正式预警。缺少历史上架与可售证据时先显示待核实；运营填写连续上架／有货起始日、凭证及核验依据，确认至昨天。核验会留痕，不能覆盖上线后已观察到的无可售事实。
- 系统上线后每分钟观察库存，库存写入时同步记录当天最小可售值。缺少观察日期不回填；从日初五分钟内开始记录且全日已知最小可售为正，才能延续可售证据。上市状态仍来源于运营核验，未对接平台在售状态 API。
- 7 / 14 / 30天分别标注关注、需处理、专项去化；30天以上显示30+，不是库存库龄。缺报、上架不足7天、库存不足分别说明原因。恢复销售或当前可售清零后自动移出预警，审批优惠本身不关闭预警。
- 每次读取按最新数据重算；服务器每分钟保存状态变化和到期提醒。同站点、渠道、SKU只有一条持续预警，不每天重复创建。其他去化措施独立留痕，不强制降价。

## 优惠流程

运营保存草稿 → 上传申请截图 → 提交财务 → 财务核算 → 管理员批准 → 运营在平台设置优惠并登记执行 → 在平台停止并恢复价格、上传凭证 → 满7天由财务复盘。

申请包含实际原价、最终优惠价、最低允许价格、优惠方式及叠加规则、数量上限、总预算（让利＋预计广告）、WIB开始结束日、商品链接、原因和量化目标。最长31天。财务填写每件到岸采购、履约、预计售后、预计广告、合计平台支付佣金费率、核算日期和来源版本。未知预测成本需补齐，不能默认为0。

普通优惠预计单件贡献不得为负；专项亏损清仓必须说明并设定足额总亏损上限，由管理员额外明确确认。金额用整数分存储。申请、财务、管理员不能由同一人自行审批。审批后条件锁定；修改只能退回草稿形成新版本，旧凭证不能替代新版本。撤回、退回、驳回及终止均保留历史。

同SKU重叠申请和仍在执行／待停止的活动会被阻止；提交、审批和执行时都检查当前可售数量。活动数量上限不预留库存，运营执行前须再次核对成本、库存与叠加规则。成本或价格条件变化需撤回并重新申请。

## 执行和结果边界

系统没有平台改价接口，批准不会改平台售价、销售或库存。运营须自行在平台设置数量、预算与截止时间，登记活动编号、实际成交价、执行说明及截图。到期或库存、数量、估算预算触及上限，会持续生成“停止优惠／恢复价格”待办，不会自动声称平台已经恢复价格。

限额监测使用活动期该站点渠道SKU的全部已导入销量（含非活动销售），为保守提醒而非活动归因；没有实时平台订单，监测准确性依赖销售及时导入。活动期内退款、退货和平台费用由财务核实。实际SKU广告费用无法归属时留空，复盘贡献显示待核实，不虚构分摊。复盘需要活动期日报完整且停止后满7天；最终结算可能继续调整，本模块不是平台结算凭证。

## 存储、维护与验收

迁移 0022 新增 availability、stock days、alerts、promotions、files 五表，所有表受备份维护锁保护。凭证使用原有私有存储桶，按申请权限读取，每版本每步骤最多6张 JPG/PNG/WebP，每张10MB。全量备份和恢复包含新表及凭证。

验证覆盖日期边界、漏报、冲销、预留库存、人工核验、审批顺序、自审禁止、权限和字段隔离、版本并发、重叠活动、预算及亏损、凭证版本、到期停止待办、备份恢复，以及真实HTTP角色访问与私有附件。上线时只新增功能和观察记录，不创建真实优惠申请、不替用户审批、不修改平台价格。
