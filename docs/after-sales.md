# 运营售后反馈

适用五站 TikTok / Shopee 运营。菜单入口“售后反馈”；管理员、供应链、工厂可查看所有已提交记录，运营仅可查看本人记录；草稿仅本人可见。前台每15秒刷新可见页面，附件访问逐次校验登录与记录权限。

## 登记与协作

1. 运营按售后发生日期登记平台售后单号、订单号、SKU、件数、该SKU的退款金额（站点原币种）、客户售后原因和说明。平台无售后号时使用稳定的内部编号。工厂、仓库、批次为追溯线索，未知留空。
2. 保存草稿，上传1–6张 JPG / PNG / WebP 图片，每张不超过10MB，再提交。遮挡图片中与处理无关的客户电话、地址等信息。证据保留服务器上传时间、内容哈希及上传人；上传时间不代表拍摄时间。
3. 供应链、工厂补充核实及处理意见。客户选择的原因不自动决定责任，也不自动触发赔偿。
4. 管理员可退回补证，或填写责任类型、具体责任方、应赔金额和判定依据。原币种金额最多2位小数；无赔偿填写0。
5. 管理员登记实际赔付日期、金额、凭证号和说明。支持分次赔付，禁止重复凭证和累计超额；已赔付后不能作废、变更责任方或将应赔调低至实赔以下。
6. 赔付结清后管理员结案；客户不想要 / 取消、与描述不符，还须运营填写沟通或链接优化措施。操作保留审计，不提供硬删除。运营未提交和待改进、管理员未结案事项会进入红色待办，跨月保留。

## 统计口径

- 售后发生月份为追溯归属月；累计实赔包含其后月份登记的赔付，不是当月现金收款报表。
- 一张售后单每个SKU一行。同站点＋渠道＋售后单号＋SKU不允许重复登记。
- 明细条数、去重订单数、涉及件数分别显示。多SKU订单不要每行复制整单退款金额。
- 草稿、作废不计入月度汇总。无记录日期不代表确认零售后。
- 原因分布、每日趋势、责任方追溯支持月度查看；币种独立相加，CSV导出遵循当前筛选。
- 该模块只记录售后及赔付，不重复冲减销售额、不自动增加库存，也不发起转账。实物退仓和销售纠错仍走原流程。

## 数据保护与验证

售后主表及图片索引纳入迁移、备份、恢复与维护锁。版本守卫防止并发覆盖，责任确认及赔付均限管理员。图片按实际文件签名验证，存放在现有私有附件存储，通过带权限的API读取。测试覆盖越权、重复、图片限额、部分实赔、并发、结案条件、币种及备份恢复，并在生产HTTP路由测试登录/附件访问/来源检查。
