# TikTok 内容中心 · 本地验收

Admin 入口为「日常工作 → TikTok 内容中心」。本地演示位于 `http://127.0.0.1:57324/?page=content-center`，只使用合成数据。演示中素材地址是示例链接。

## 团队操作

| 谁 | 在哪里操作 | 操作结果 |
| --- | --- | --- |
| 站点运营 | 需求与排期 → 新建需求 | 选择来源和真实 SKU，填写顾客、主卖点、脚本、镜头和需要交付的日期。达人视频从已有合作中选择已验收内容。 |
| 拍摄剪辑 | 安排拍摄 → 交付新版本 | 确认拍摄及交付日期。同款需求可关联到同一拍摄日。每个剪辑版本保留脚本、成片地址和可选的原始镜头目录。 |
| 写 AI 脚本的运营 | 在自己的站点交付新版本 | 保存提示词、产品参考和生成成片，确认已核对实物和发布标识。 |
| 需求站点运营 | 脚本与素材 → 验收通过或退回修改 | 退回时指出需要改动的镜头。再次交付产生新版本，保留旧版意见。 |
| 其他站点运营 | 脚本与素材 → 用此脚本创作或认领发布 | 沿用脚本会建立有来源的新需求。认领已验收版本时选择本人负责的站点、账号、语言、流量类型、本地改动和计划日期。 |
| 发布人 | 站点发布 → 登记已发布视频 | 先在 TikTok 发布，再登记完整视频链接与实际时间。账号需与计划相符，同一视频只能登记一次。 |
| 站点运营与拍摄剪辑 | 效果复盘 → 复盘决定 | 运营回填观察数据。复拍决定生成新需求，跨站测试生成目标站发布任务，暂缓决定保留原因、责任人与跟进日。 |

## 素材与数据

- 达人原版默认仅供参考。管理员或运营主管依据实际合作凭据登记可用站点、直接发布或二剪用途及截止日期。来源重新验收、授权撤销或到期后，系统重新核对可用范围。文件实际访问权限仍由存放媒体的共享空间控制。
- 实拍和 AI 采用共享链接存放成片。AI 生成、视频上传、TikTok 发布和取数均由负责运营在相应工具完成。
- 发布后 24 小时、7 天分别保留累计快照，后续修订保留记录。未取得的数值留空，已确认的零填写 0。达人原片的 7 天和 30 天直接引用达人模块。对比参考按相同站点、账号、自然或投流分类计算其他视频的 7 天播放中位数，并显示样本数。
- 「拍摄剪辑」是内容中心专用岗位，正式启用时由管理员将实际账号分配到该岗位。站点运营沿用本人 TikTok 站点和已配置店铺的主责／备份分工。

## 本机复现

从本工作区运行本地 Node 构建后，在同一工作区执行下列命令。首次建演示库时使用第一行，已有演示库应直接运行第二行。预览服务绑定本机回环地址，独立于正式数据目录。

```sh
node scripts/content-center-preview.mjs
LOONGJUMP_CONTENT_PREVIEW=1 LOONGJUMP_DATA_DIR="$PWD/work/content-center-preview" node scripts/content-center-preview-server.mjs
```

角色入口为 `/__preview/admin`、`/__preview/studio`、`/__preview/id`、`/__preview/my`，分别对应演示管理员、拍摄剪辑、印尼运营、马来西亚运营。多个入口在同一浏览器中切换同一个演示身份。
