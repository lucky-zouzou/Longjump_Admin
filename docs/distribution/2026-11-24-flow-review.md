# 分销流程梳理与本地验收范围

依据：用户提供的《线下分销分为.docx》。本次仅本地开发，不修改生产数据、不自动发布。

## 判断与实现原则

文档将国内直发、印尼库存销售与免费营销样品分开是合理的。关键不是增加一个“完成”按钮，而是让商品履约、资金核销、合作内容各自有可追溯事实。

|业务|主要流转|资金及库存边界|
|---|---|---|
|国内线下分销|供应链建客户和报价 → 客户确认报价 → 合同与结算条款 → 独立审核 → 工厂真实货源和打包 → 财务放货核验 → 实际发货 → 签收及对账|CNY 分单位；工厂直发单独记账，不扣印尼、海外或海运库存。先款或定金按合同达到放货门槛，账期与寄卖保留待回款。|
|印尼线下销售|销售申请 → 供应链核库存和价格 → 预留 → 客户确认 → 满足付款或获批信用条件 → 正式出库指令 → 物流派仓 → 新打包照片 → 运单与实际出库 → 责任销售签收|IDR 台账；付款截图不是到账；净实际到账冲正后重新核验；每批实际出库扣库存。|
|印尼 TikTok BD 寄样|客户/达人及协议 → BD 申请与成本单 → 供应链审库存 → 物流派仓 → 照片和运单 → 实际出库 → BD 签收|只用印尼 TikTok 已建库存份额；免费样品不计收入、客户应收。实际出库样品成本和运费分列，财务核实后归集到印尼 TikTok 运营。|

## 重要规则

1. 物流、仓库均选择实际负责账号，不把“文桃”写死为代码里的某个人。管理员先维护供应链岗位账号，再按订单指定物流与仓库执行人。
2. 新客户、订单采用 CN/ID + 六位随机数字；保留前导零、检查重号，不覆盖旧编号。公司简称由业务人员明确填写，不从全称自动猜测。
3. 客户确认付款单与正式出库指令分别导出。确认单不能作为仓库放货授权，正式指令关联订单并保持唯一。
4. 客户加单可另开新单；未发单退回销售后重新送审。原记录、数量、价格和关联新单保留，不能直接改已签发出库指令。
5. 未付款超时预留仅在没有资金记录、没有待核付款凭证且尚未出库时自动释放；存在疑点交财务和供应链核对，不误放库存。
6. 分批发货每批使用未使用的打包照片；Lalamove 同样必填订单编号，不用照片代替运单。
7. 签收和财务核销独立；寄卖客户实际售出后才确认结算。样品签收不关闭约定视频/直播任务。
8. 仅寄样、不承诺内容交付必须在印尼 TikTok 合作需求中明确选择，并通过协议流程；不能以留空视频数量代替，也不能在确认后抹去承诺。
9. 财务已关账期间禁止回填或冲正，须先按原有反关账流程处理。国内子账与寄样费用纳入月结快照，旧快照缺项不使用当前数据冒充历史结果。
10. 国内子账、印尼销售、寄样费用分别展示；合同待收、已发应收、预收不能简单相加，不将局部贡献称为全公司净利润。
11. 历史订单保留原流程和编号；新建印尼销售强制新流程。旧印尼 TikTok 寄样接口不能绕过新库存流程，已发生的历史物流事实不追溯重复扣库。
12. 印尼线下页面支持中文、Bahasa Indonesia 按账号切换，业务编码和金额不随语言变化。客户自填名称和备注保留原文。

## 操作入口

- `?page=domestic-distribution`：国内线下分销，管理员/财务/负责供应链/获分配工厂。
- `?page=wholesale`：印尼线下销售，延续原销售入口与客户目录。
- `?page=marketing-samples`：印尼 BD 寄样，按责任人展示审核、派仓、打包、签收和成本待办。
- `?page=distribution`：原商家独立登录、申请和账号管理保留。
- 小品同学新增流程指南，按实际账号及站点渠道权限给入口。

## 本地预览

使用 `scripts/distribution-preview.mjs` 的固定合成夹具；`scripts/distribution-preview-server.mjs` 仅监听 `127.0.0.1:57341`，外部调用关闭，不能操作生产账号或生产数据。

预览入口 `/__preview` 提供管理员、财务、供应链/物流、仓库、工厂、印尼销售、BD 七个演示岗位。演示订单和凭据均为 TEST-ONLY。

国内工厂直发目前登记真实货源、装箱、发货事实，不是国内工厂完整库存或制造成本系统；不伪造可用库存、成本和工厂对账结果。
