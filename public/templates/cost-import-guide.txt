# 成本利润透明：本地第一版

这是待评审的本地实现，不代表已部署。导航入口为“成本利润透明”，地址 `/?page=cost-profit`。不改库存、不自动调价或投放、不自动发送消息。

## 录入流程

1. 先在现有商品主数据建立 SKU。成本账册不新建商品或库存。
2. 供应链在发运前填写“商品批次成本”模板。支持现有 Excel/CSV 组件：`.xlsx`、`.xls`、UTF-8 CSV。每次最多200行、20票、10MB；含公式的表格拒绝。保留模板中文表头，也支持字段英文名。表头自动映射，预览列即映射结果；不支持任意自定义字段映射。
3. 页面依次执行“文件字段预览 → 服务端校验与分摊预览 → 确认整批写入”。任意错误、重复业务键或并发版本变化都会阻止整批提交。取消不写库。提交后每票待独立财务复核。
4. 财务查看原币、汇率版本、来源和分摊，选择税费分类：存货成本、期间费用、可抵扣/待收回、不适用。录入人不能复核自己的版本。暂估可复核，但一直保留暂估标记；缺失/待确认仍阻止完整贡献。
5. 财务在“结算录入”选择现有真实销售来源、成本票次、票内行号及数量，填写收入、平台/达人费、广告、退款损耗、仓库费用和依据。来源销售冲销或改动后，相关贡献自动降级为待核实。
6. 已扣平台/达人佣金的净结算款可选 `net`：系统先补回该佣金展示收入，再扣一次费用。若净结算还扣了运费、退款等其他金额，请先还原收入，使用 `gross`。退款只录尚未从收入扣除的部分。收入与结算费用使用同一原币/汇率版本，成本票可使用不同原币。
7. 共享广告：订单选择“费用池分摊”，直接广告填0、不适用。财务在共享广告页选择订单，按已登记收入分摊整笔费用，合计守恒；一个订单只能关联一个费用池。收入/佣金依据变化后，须修订费用池，否则贡献待核实。
8. 后补费用仍用原成本票号、原行号和完整商品行导入，`当前修订号`填目前版本，明确修订原因。金额、状态、汇率及证据可以修订；SKU、子批次、数量、分腿、仓库和生效日期不能在成本修订中改变。新版本复核前，相关贡献待核实。旧成本、旧结算/模拟快照均不覆盖。

## 模板字段

空白模板：`public/templates/cost-ticket-template.csv`，文档副本：`docs/templates/商品批次成本导入模板.csv`。运行系统后可通过页面下载 Excel 模板或 CSV 模板。模板没有演示商品数据。

|中文列名 / 英文名|填写说明|
|---|---|
|成本票号 / businessKey|全局唯一的成本计费票次。建议用运输目的地分腿单号。不可含竖线。一个物理柜分多个目的地/渠道时，须先凭承运商账单确定各成本票范围，不能把同一整柜费用在每个分腿重复录入。|
|站点 / site；渠道 / channel|站点为印尼、马来西亚、泰国、越南、菲律宾；渠道为TikTok、Shopee、线下分销。|
|登记日期 / businessDate；成本生效日期 / effectiveAt|YYYY-MM-DD。已售关联日期不得早于生效日期。|
|当前修订号 / revision|新票填0；更新v1填1。整票完整替换成新修订，而非增加数量。|
|新增或修订原因 / reason|填写为何新增或修改以及证据变化。|
|仓库 / warehouse；系统运输分腿ID / legId|仓库必填。已有系统分腿时填ID，服务器校验站点、渠道、仓库和完整SKU数量。外部票可留空ID，但不会显示为系统链路已验证。|
|票次凭据 / ticketSource|提单、订舱单、发运单等编号或链接。第一版保存引用，不自动读取外部文件。|
|票内行号 / lineKey|每个来源子批次一行，同票唯一。重复SKU可用A、B等不同行号。不可含竖线。|
|SKU / sku；采购生产子批次 / batch|必须是现有SKU；子批次填写可核实的采购/生产来源凭据编号。外部子批次引用不等同于自动系统追踪。|
|数量 / qty|正整数，指该子批次在本票的数量。|
|总体积立方米 / volume；总重量千克 / weight|该行全部数量的合计体积/重量，非单件。所选分摊依据必须各行大于0；其他依据可明确填0。|
|原币单件采购生产成本 / unitCost|单件材料/采购生产合计；不要重复加已包含在采购总价里的材料费。未知留空并选missing/pending。|
|商品成本状态 / productState|见下表。|
|商品币种 / currency；商品兑CNY汇率 / fx；商品汇率版本 / fxVersion|支持CNY、USD、MYR、IDR、THB、VND、PHP。汇率是1原币兑换多少CNY，CNY必须为1。版本填写来源与日期，保存后默认汇率更新不会改写此版本。|
|商品凭据或缺失原因 / productSource|采购发票、报价单、对账单等；缺失时写原因。|
|海运原币整票总额 / seaAmount；税费原币整票总额 / taxAmount|整票总金额。同票各行重复填同一金额，系统只计算一次，不能填每行分摊额。|
|海运/税费状态 / seaState、taxState|各自明确状态；有税无税逐票维护。|
|海运/税费币种、兑CNY汇率、汇率版本|seaCurrency/seaFx/seaFxVersion、taxCurrency/taxFx/taxFxVersion。海运/税费可以和商品使用不同币种。|
|海运/税费凭据或缺失原因|seaSource、taxSource。|
|海运/税费分摊依据|seaBasis、taxBasis：`volume`总体积、`weight`总重量、`qty`件数。按承运商实际计费依据选择，并在来源说明原因。|

同票的站点、渠道、日期、仓库、分腿、生效日期、修订号、票据、海运/税费字段必须一致。金额以CNY分为单位分摊，余数确定性分配，原币与汇率完整保留。

|状态|金额要求|含义|
|---|---|---|
|actual|正数|已知实际，有凭据|
|estimated|非负数|暂估，保留估算标记|
|pending|留空|待确认，无可用估值|
|missing|留空|缺失，必须写原因|
|zero|明确0|已核实零费用|
|not_applicable|明确0|不适用，有说明|

## 口径与限制

- 报告币为CNY。成本链按来源子批次、成本票、仓库、销售关联、费用结算展示。公司期间费用、可抵扣税和公司净利润另口径，本页不声称公司净利润。
- 整票采购支出不全部作为已售成本。每个成本分项按该子批次累计关联数量分配到已售和未关联余额；剩余分额守恒。未关联余额是本成本账册余额，不是物理仓库盘点库存，历史销售尚未补录时尤其不能混同。
- 现有系统主要提供SKU日销售汇总。首版人工关联销售来源，单一结算可包含多条子批次。批次依据必须选“出库凭证人工关联”或“明确计价约定”。没有自动仓库逐订单批次追踪；来源子批次的外部凭证真实性需业务复核。
- 结算贡献以财务录入的结算收入及费用为准；自动检查销售数量、SKU、日期和站点渠道，但不自动对接平台逐单收入对账。全部销售未建立结算关系时，页面明确显示未关联销售，不推断全公司利润。线下批发目前需先有对应sales_records来源，本版不自动接入寄售/批发收入确认。
- SKU/成本票筛选选择包含该商品的整张结算单，显示整单收入和费用，避免多SKU订单重复基本费；不是独立SKU净利润分摊。日期过滤结算，不截断成本票历史。
- 收入与费用修订显示相对结算首版保存快照的分项差额，不将差额解释为未经验证的因果，更不直接追责。已有行动单通过链接承接责任人、执行与复查，不自动创建问题、改变行动状态或发消息。
- 市场证据人工维护同国家、同平台、材质、尺寸、档次、排名依据、链接、日期、展示/促销价、运费、优惠条件、库存；没有未经许可抓取。超过14天/库存不确定会降级。市场价格不是实际成交价；本版不录公共销量估计。可比性由记录人提供依据，不自动断言所有竞品可比。
- 测算输入统一CNY，成本来自选定已复核批次，市场对照使用已有人工证据。测算保存独立快照，不自动调价/投放。暂未自动整合既有新品调研的非结构化价格，页面提供入口复用其证据。
- 第一版不提供成本数量冲销或票次撤销入口：数量/来源关联错误应停止进一步核算并由开发/财务制定明确纠错迁移；不能用成本导入更改库存。暂不替代ERP总账或税务申报。

## 权限与数据安全

迁移不修改真实用户角色、不自动授予成本权限。管理员可查看/录入；其他支持岗位须显式启用 `cost_access`，财务复核只允许财务岗位且独立于录入权限。运营的市场证据/模拟快照保存也须录入授权，只读授权不能保存；运营始终限制本人站点渠道；工厂、海运、销售不开放。成本权限的实际开通需另行批准，在部署评审中确认账号清单。本次仅为隔离测试账号赋予测试权限，未变更真实账号。

`cost_access`字段：`user_id`、`can_read`、`can_write`、`can_review`。不提供匿名或前端开关绕过。业务记录、复核和导入记录不可更新/删除；修订追加新版本。写入同事务保存系统审计。所有新表纳入现有动态全量备份及迁移版本清单，并遵守维护锁。

## 开发检查

推荐按仓库原规范执行 `pnpm check`、`pnpm build:server`、`pnpm build`、`node --test tests/*.test.mjs`。隔离副本复用已有依赖时，pnpm11可能自动尝试安装依赖；禁止安装的环境请直接运行已有工具：

```sh
node scripts/backup-manifest.mjs --check
node node_modules/typescript/bin/tsc --noEmit
node server/build.mjs
node node_modules/vinext/dist/cli.js build
node --test tests/*.test.mjs
node node_modules/eslint/bin/eslint.js . --ignore-pattern dist --ignore-pattern dist-node --ignore-pattern .next
```

`server/build.mjs`改用当前Node调用已安装vinext，避免包管理器自动安装。隔离副本依赖入口为本地目录中的只读符号链接，Vite缓存放在`.vinext/vite-cache`。不要对原工作区安装、清理或覆盖依赖。

专项夹具：`tests/cost-fixture.mjs`（仅测试）；`tests/cost-profit.test.mjs`（金额、修订、回滚、缺失、鉴权）；`tests/server.test.mjs`（真实HTTP入口）。测试样本从不进入生产或正式看板。

## 本地可重复预览

先完成服务端构建，然后运行 `node scripts/cost-profit-preview.mjs`，它只创建全新的 `work/cost-preview` TEST-ONLY 数据库，不覆盖现有数据库。再运行：

```sh
NODE_ENV=production LOONGJUMP_DATA_DIR="$PWD/work/cost-preview" LOONGJUMP_COST_PREVIEW=1 node scripts/cost-profit-preview-server.mjs
```

仅监听 `127.0.0.1:4317`，打开 `http://127.0.0.1:4317/?page=cost-profit`。此独立验收入口固定使用测试用户，不创建凭据、不运行自动监测；不得作为正式服务启动命令。正式服务仍使用原 `server/index.mjs` 真实登录和授权路径。结束验收后终止进程。当前安装依赖的开发模式有RSC重复导出错误，因此验收使用生产构建，不安装/升级依赖。
